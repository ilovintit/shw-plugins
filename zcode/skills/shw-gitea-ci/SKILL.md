# CI 取证

接入/迁移先读 [项目模板](references/project-template.md)；访问方式见 [配置](config.md)。构建输入和内部依赖规范按 `shw-test-spec/references/ci-config.md` 与 `ci-cache.md`。

测试与开发、集成、发布、部署解耦：单元、API、E2E、VRT、回归及冒烟均仅在用户明确要求后，在专用 Mac mini 的本地隔离工作区固定提交执行。普通 push/PR/tag/部署不触发测试，线上 test 分支测试入口退役；未测试不阻挡已授权发布。必要构建/编译、静态与配置检查、来源核对正常执行，不得借“检查”名义运行测试；构建成功不代表测试或人工验收通过。

读取真实 run/job/日志与工件，区分排队、运行、失败、取消、跳过、过期与通过。汇总绿不代表缺失的 required job 成功。网络失败或工具结果未知先回读，不重复触发变更。

失败按日志定位根因；构建/部署失败与测试失败分开；测试重跑限明确授权的Mac mini 本地独立测试任务，不能因发布自动触发。不得删断言、放宽门禁、全量接受快照、只为旧测试绿而回滚正确行为。

取证包括 run URL、job结果、精确候选、实际构建制品digest；仅测试任务另记基线revision与coverage。当前HEAD或目标基点漂移后旧成功不能放行。只有必要时读失败日志，避免把凭据和业务数据复制到报告。

## PR 工作流来源与正常合并

核对服务端版本、实际事件、工作流来源 revision 与 checkout revision，不能仅因补丁尚未进入 dev 就断言 PR 执行旧流程。Gitea 1.27.3 的普通 `pull_request` 取 head 工作流，`pull_request_target` 取 base 工作流（[固定版本源码](https://github.com/go-gitea/gitea/blob/v1.27.3/services/actions/notifier_helper.go#L107-L264)）；仍须以当前 run 事件和来源核实，其他版本重新确认。工作流来源不等于被检出的代码提交；带凭据的 target 事件不能因此执行不可信 head 代码。

合并决策先读 `shw-gitea-flow/references/merge-authority.md` 并识别实际 PR 类型。dev→main（含冻结 dev 的集成分支）由用户手动合并：Agent 完成必要检查后提供 PR 与证据，CI 绿不授予代合并权限。其他 PR 在实际检查、审批与合并授权满足后继续正常合并；不能把所有 base=main 的 PR 都当成 dev→main。

合并被拒绝不能一律停工。dev→main 回读后反馈给用户手动合并，剩余检查继续跟进；其他已授权由 Agent 合并的 PR，先回读是否已 merged，再检查当前 HEAD 门禁：排队/运行中则持续有间隔跟进，失败/缺失/取消则读取日志与触发原因、在授权内修复并跟进新候选，通过后重试正常合并。门禁全绿仍拒绝时继续核对审批、冲突、基点漂移、合并方式与可读保护信息；仅确切权限/人工审批或授权内无法处理的阻塞反馈用户。

无法读取全部分支保护细节本身不是一律停工理由，403/405 也不单独证明权限问题或门禁未完成。不 force/admin 绕过、不切换身份或入口规避拒绝、不将 skipped 当 passed；不为推进门禁运行未授权测试。合并前回读 HEAD 与最新检查，成功后核对合并提交和对应部署；历史成功不替代当前提交。

## 合并后的部署任务

回读准确 merge SHA 对应的构建、上传与部署任务，继续核对实际运行版本和环境状态；PR Gate 通过不等于部署完成。T3 PR watch 在合并后停止，不能充当部署观察器；按宿主可用事件/持续任务机制跟进，无事件订阅不单独构成阻塞，当前轮可只读推进则继续查询与诊断；只有实际无法继续时明确部署未确认与恢复入口，不能称交付完成。完整证据与通知规则见 shw-delivery。
