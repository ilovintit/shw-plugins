# 派发行为场景

维护技能和升级插件时审查以下场景的实际决策；不要用固定文案关键词断言替代行为审查。

| 场景 | 应有行为 |
| --- | --- |
| 无 Git 的资料分析任务，用户允许子代理 | 读取通用模型表，核实当前宿主能力并传上下文；不要求 Issue 或项目模式。 |
| 有 `.shw-workflow-ignore` 的目录，用户明确要求通用派发指导 | 保留用户要求及目录权限；不自动开启 SHW 生命周期。 |
| Codex 可用指定模型/档位，主代理模型不同 | 显式传表中 model/effort 与 none 或有限历史，补充必要上下文，不用默认 all 继承。 |
| 宿主只允许继承，主代理模型或档位不匹配 | 报告差异，主代理继续可做工作，不静默派发其他模型。 |
| Kimi/ZCode 提供 thinking 开关但没有可验证最高档位 | 区分开启思考与最高档位；不猜 high/max，不改用户配置。 |
| 模型正确但环境强制覆盖 effort，或复用旧代理参数不同 | 核验实际绑定并报告；不以请求提示或继续消息声称参数已变更。 |
| 宿主禁止委派，或任务工作区所有权未知 | 技能不授予派发/写权限；不借子代理绕过限制。 |
| 更新插件后模型目标改变 | 以新表指导后续派发，保留既有用户配置/缓存；重新核实已有代理设置。 |
