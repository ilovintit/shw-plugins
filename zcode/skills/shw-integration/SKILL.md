执行前必须读取 `shw-issue-gate`；修改前读取 `shw-workspace` 并确认项目、目录、Issue 与所有权。项目外只读，未知修改不覆盖；能力缺失不扩大授权。

# 集成到 main

读取 [候选来源契约](references/candidate.md)、[合并执行人与推进规则](../shw-gitea-flow/references/merge-authority.md)、`shw-verify`。冻结已授权范围的 dev SHA、main 基点和预合并 tree，创建或复用集成 PR，保护未知修改与并行占用；未来 dev 推送不自动纳入。dev→main 默认交用户手动合并，集成/发布请求不授予 Agent 代做该动作的权限。

集成仅做代码/文档审查、必要构建/编译、配置与来源核对，不触发或等待单元、API、E2E、VRT、回归或冒烟。人工体验可按用户安排在生产发布后进行；未体验/未测试如实记录，不默认阻挡明确授权的集成和发布。

持续跟进当前候选的必要构建和门禁，处理授权内失败；准备就绪后提供 PR 链接、冻结范围、检查结果和后续计划，请用户手动合并。不调用 merge/auto-merge，也不经网页、其他工具或 push main 代做。若合并尝试被拒，按人工边界回读并交接；只读查看原因不等于继续换入口尝试。

用户手动合并后，回读实际 merged、目标 main、父提交、tree、SHA，确认与候选一致再继续既有发布授权。候选或目标变化时重算差异及构建输入，不因此触发回归。保留实际构建来源与 main 提交映射，不能把历史构建结果套在新内容上；未实际合并不提前打生产 tag。

用户主动测试使用专用 Mac mini 本地固定源码，不创建线上 test 候选，保留历史分支；本地报告不作为 main 来源。测试基线不绑定集成放行，不自动更新。需要测试时按 `shw-test-spec` 的明确请求执行。

存量测试required checks须在该项目授权范围内正常迁移工作流/保护配置；不得force合并、伪造成功或把skipped称为passed。插件更新不等于其他仓库已迁移。
