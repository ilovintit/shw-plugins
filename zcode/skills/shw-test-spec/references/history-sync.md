# main 回灌纯历史同步

首次 dev→main 发布检查和真实内容变化必须实际启动全量自动化。只有同一仓库、同一发布 PR 的 main 回灌可免重复构建/测试：

1. 当前 HEAD 是双父 merge，第二父为当前 main，文件 tree 与第一父相同；不按提交标题推断。
2. Gitea 证据对应同一仓库、PR、dev→main 方向、第一父 SHA 和当前 main SHA；工作流身份须匹配真实发布检查。
3. 对应最新运行已 completed/success，有有效完成时间；实际全量步骤执行成功，不能引用 skipped、失败、取消、仍运行、其他PR或复用记录。
4. 查询有界且只读。权限/网络/格式/分页预算不足均回退实际全量，不把查不到当作成功。

本仓库 ci-plan.mjs 最多查询5页各50条运行，20秒总预算；验证 pr-gate.yml 的唯一 gate job 及全量执行步骤。输出 history-sync 计划，记录 evidenceRun/evidenceSHA/当前head/base，工作流跳过构建和测试。Gitea仍会创建轻量判定run以给新SHA提供可追踪的受保护状态，这不是完全不产生Actions记录。连续同步不能以复用记录递归替代实际全量证据。

业务项目按自己的门禁工作流/job/全量执行步骤建立等价核验，不照搬本仓库名称。main→dev纯同步PR无内容差异时只需轻量检查；Hotfix回灌含实际改动时仍定向验证。部署、安装验收和发布审查保持各自证据边界，不用CI复用声明代替。
