# 选择器、隔离与报告

## 项目入口契约

项目自行实现并在AGENTS/测试说明中给出真实命令，例如 `<项目测试入口> --module orders` 或 `--file <具体测试文件>`。这里是接口形态，不要求项目新增同名命令；已有./dev等路由则按其实际能力执行，不绕过或伪造子命令。

每个API/E2E/VRT套件应提供：类型、模块/文件选择、需要的前置、用例清单预览、执行报告路径。未选择、未知选择器或匹配零用例应失败；“没有适用测试”须由变更映射明确判定并在CI计划中记录，不能靠拼错文件得到绿。

测试与模块对应关系随代码维护：新增模块、移动/删除文件、共享组件或配置变化都要更新映射。Issue→dev只选实际关联模块，禁止全量兜底；如果映射遍及全仓，明确各模块内实际受影响的用例/文件。dev→main必须实际执行完整测试矩阵，无历史结果复用跳过路径。

## 数据与外部依赖

沿用shw-backend-stack的每run隔离中间件口径，测试账号、schema/库、对象前缀和文件均与真实业务数据隔离。清理在失败/取消路径也执行。第三方依赖能否stub、哪些用例必须真实连通由test-plan明确；不以生产凭据或共享生产数据换取方便。

API用例的前置与断言独立，E2E从明确状态进入业务流程，VRT使用稳定数据与渲染条件。浏览器状态、用户会话和测试数据不依赖上一文件残留。等待必须有超时与具体诊断，重试不抹掉第一次失败证据。

## 验收证据

每次CI输出当前SHA、PR方向、变更文件、所选模块/文件、执行用例与未覆盖范围。失败报告包含可定位的日志/trace/截图/数据准备错误；VRT保留expected、actual、diff和环境信息。

本地快速单测单独记录，不能冒充PR CI；E2E浏览器通过不证明小程序/iOS/Android真实设备通过；VRT只证明视觉比较，不替代业务行为验证。人工验收及豁免继续走shw-acceptance/test-plan。
