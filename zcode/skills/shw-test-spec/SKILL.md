# 独立测试与基线

测试与开发、集成、发布、部署解耦：单元、API、E2E、VRT、回归及冒烟均仅在用户明确要求后，于独立 `test` 分支的固定提交执行。普通 push/PR/tag/部署和推送 test 分支本身不触发测试；未测试不阻挡已授权发布。必要构建/编译、静态与配置检查、来源核对正常执行，不得借“检查”名义运行测试；构建成功不代表测试或人工验收通过。

## 明确请求后的执行

1. 先核对用户本次测试请求、范围与目标源码 SHA；“修复”“发布”“继续”和历史测试授权不自动构成新的测试请求。仅有测试计划不表示授权执行。
2. 使用 `test` 分支承载独立候选。读取远端当前 tip、占用与未完成任务；首次可按授权从选定提交创建，已有分支只能安全快进或经正常合并准备候选，不强推、不重置、不覆盖其他人的测试。存在差异时报告确切实际测试 tree，不能冒称等于原源码 SHA。
3. 只有显式手动入口执行测试，工作流同时校验 `workflow_dispatch` 和 `refs/heads/test`；分支存在、push、PR、tag或定时任务不自行启动。测试命令和范围取自本次请求；复测也限已授权测试任务，不因后续生产发布自动重跑。
4. 需要运行时再读取 [执行与覆盖](references/execution.md)，使用隔离且受控的测试资源，不因用户在生产体验而自动向生产发测试请求或写测试数据。
5. 保存请求范围、test SHA、来源 SHA/tree、命令、实际结果、日志和未覆盖项。partial不是全量，未运行不是通过。测试结果及基线不自动触发发布、回滚或阻塞dev/main合并。

基线仅在该独立测试任务中，按用户认可的预期行为维护。无旧基线不阻止正常发布；禁止删断言、全量接受快照或改阈值伪造通过。已发现问题如实报告并按用户决定另行修复；不要隐瞒问题，也不把测试任务的失败变成默认生产门禁。

工具链和内部依赖见 references/ci-config.md、ci-cache.md、ci-images.md；分支/结果恢复见 references/history-sync.md。保留测试实现供按需使用，不把 test 作为开发到生产的必经分支。

测试状态按提交SHA而非分支隔离：test候选必须是独立的test-only提交，不能是dev/main当前可达的提交。准备候选时保留选定源码SHA和tree，可以用相同源码tree生成仅供test的快照提交；保护已有test历史，不强推或重置。手动入口刷新dev/main引用并拒绝会把测试状态写到开发/发布提交上的候选。test快照本身不合入dev/main，修复走普通Issue分支；运行报告同时记录test SHA与原始来源。
