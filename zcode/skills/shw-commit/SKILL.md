# 任务完成后主动提交

## 概述

任务完成不是终点——**改动留在工作区不提交，等于没交付**。未提交的改动会丢失、被覆盖、或混入下一次任务，造成混乱。

**核心原则**：任务完成的最后一步是 commit，不是汇报。每次任务成果都应自动落盘到本地 git，由用户决定何时推送。

**这是主 Agent 的自律行为，不是用户该催的事。**

## 铁律

```
任务完成 + 有未提交改动 + 用户未拒绝 → 必须 commit
绝不 push —— push 是用户的行为，不是你的
```

## 门禁函数

```
任务完成（无论大小：改代码、写文档、修 bug、配置调整）后：

1. 检查：当前目录是否 git 仓库？
   - 否 → 跳过，任务汇报里注明"非 git 仓库"
   - 是 → 继续

2. 检查：git status 是否有未提交改动？
   - 无 → 跳过，不需要空 commit
   - 有 → 继续

3. 甄别：改动是否属于本次任务？
   - 排除 .gitignore 已处理的（不要 add 被 ignore 的文件）
   - 排除明显是测试垃圾的临时产物（如 .tmp/、.cache/、.DS_Store）
   - 只 add 本次任务相关的改动

4. 排雷：暂存前检查是否含敏感文件
   - 扫描 staged 文件名：.mcp.json / .env / *.key / secret* / credential*
   - 若命中 → 停止，向用户报告"检测到疑似敏感文件"，不要 commit
   - 确认安全 → 继续

5. 提交：写有意义的 commit message
   - 用中文，简洁，带类型前缀（feat/fix/chore/doc/refactor）
   - 第一行 ≤ 50 字，概括本次任务
   - 空行后写要点（如有多个改动）

6. 停手：commit 完成，绝不 push
   - 汇报里告诉用户"已提交到本地，未推送"
   - 让用户决定何时 push
```

跳过任何检查步骤 = 失职。

## commit message 格式

```
<type>: <本次任务做了什么>

- <要点1>
- <要点2>
```

**type 取值：**
- `feat`：新功能、新文件
- `fix`：修 bug
- `chore`：杂务、配置、版本号、依赖
- `doc`：文档
- `refactor`：重构（不改行为）

**示例：**

```
feat: 归档自动 git commit + propose task 拆分粒度指引

- shw-archive 新增第6步 Git commit
- shw-propose 新增 Task 拆分粒度指引章节
- 版本号 0.2.0 → 0.2.1
```

```
fix: 修复用户登录 token 过期未刷新的问题

- 添加 token 过期自动刷新逻辑
- 补充对应的单元测试
```

## 常见情况

| 场景 | 行为 |
|------|------|
| 改了代码、跑通测试、任务完成 | ✅ commit |
| 改了文档/配置 | ✅ commit |
| 修了 bug、验证通过 | ✅ commit |
| 只读操作（查资料、看代码、跑测试没改动） | ⏭️ 跳过（无改动） |
| 改了又改回原状（git status 干净） | ⏭️ 跳过 |
| 用户说"先别提交" / "先看看" | ⏭️ 尊重，不 commit |
| 用户说"等会一起提交" | ⏭️ 尊重，不 commit |
| 不在 git 仓库（如 /tmp） | ⏭️ 跳过，注明 |
| 检测到 .mcp.json / .env 等敏感文件 | 🛑 停止，报告用户 |

## 红旗 - 停下重新评估

- 准备 push（除非用户明确要求 "push 一下"）
- 准备 `git add .` 一把梭（不分青红皂白加全部）
- 准备 commit message 写 "update" / "修改" / "wip"（无信息量）
- 准备 commit 但没扫敏感文件
- 改动跨越多个不相关任务却塞进一个 commit
- 用户本次对话多次说"先别提交"却想 commit

## 与 shw-archive 的关系

`/shw-archive` 命令内有自己的 git commit 步骤（归档专用 commit）。两者不冲突：
- `shw-archive` 的 commit：归档流程的特定 commit（提交归档目录 + spec 同步）
- 本 skill：通用行为约束（任何任务完成后 commit）

若刚跑完 `/shw-archive`，工作区已干净，本 skill 检查后自然跳过，不会重复 commit。

## 例外：何时不触发

**用户拥有最终决定权。** 以下情况不 commit：
- 用户在本次任务中明确说"不要提交"/"先别提交"/"等一下再说"
- 用户在本次任务中已经手动 commit 过（避免抢用户对 commit message 的控制权）
- 改动是探索性/实验性的（用户说"试一下"、"看看效果"）

**判断不清时**，问一句："要我把这次改动 commit 到本地吗？"——而不是默默不提交。

## 底线

**任务完成的标志是 commit，不是"我做完了"这句话。**

改动留工作区 = 任务没真正完成。commit 到本地，让用户掌控推送时机。

这是主 Agent 的默认行为，不是可选项。
