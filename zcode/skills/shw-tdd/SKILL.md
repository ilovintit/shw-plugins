**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

# TDD：测试先行，CI 判定

1. 从 Issue AC 与 test-plan 取得稳定 `TC:` 用例名。先写能证明目标行为缺失的最小断言，并自审其失败原因。
2. 将测试提交到本 Issue 分支，创建或更新同一草稿 PR；推送并等待 CI 红色结果。必须读日志确认红在目标行为，而不是编译、语法、网络或测试环境错误。
3. 保存红色 head SHA、run/job 与失败断言，再写满足 AC 的最小实现。
4. 本地默认只做 build/typecheck；推送实现后确认同一 PR 的最新 HEAD 所需 CI 全绿，再重构并重新验证。
5. 测试和实现留在同一个 Issue/分支/PR；只有交付完成才移除草稿状态并合并。

已有可靠复现测试可直接使用其对应 CI 失败证据。纯文档、配置说明或不改变行为的修正不制造假红测试，应记录适用性并以内容审查、构建、契约检查取证；带运行时变化的同一 Issue 仍需实际红绿。

用户明确要求本地测试时服从用户授权与宿主规则，记录环境和结果；本地结果不能替代合并所需的 PR CI。若 AC 无法表达，先收敛契约，不能用大量 mock 自证。
