# 证据契约

每个结论给出对象、精确 revision/SHA、动作、结果、可访问日志/工件/引用及未覆盖范围。未运行不是通过；partial 不是全量；工具调用成功不是业务成功。

- Issue：diff审查、同变更规格、必要构建、部署来源及人工体验状态；记录类型检查、受影响模块单元/API 快速测试的真实结果。
- 集成：dev SHA、main base、预合并 tree、PR HEAD、验收范围、基线 revision、所有适用检查与差异处置。
- 合并：实际 main merge commit和tree、父提交与冻结候选关系；dev SHA不等于main SHA。
- 发布：已通过集成提交、tag/审批、对应制品 digest、部署 revision；不另跑 tag 测试。

读真实日志/状态而不是推断；敏感值只保留安全引用。漂移、缺失证据、失败、权限阻塞分别说明。不因赶进度删断言、伪造检查或扩大授权。

## 命令与外部能力取证

类型/静态检查、构建、快速模块测试、全量回归分别记录命令、范围、退出码与提交；构建通过不代表类型或 API 行为通过。非交互 CLI 显式保持调用方 cwd，按其协议关闭 stdin/发送 EOF，等待真实退出码；进程启动或会话返回不等于调用完成。执行后重读当前远端 SHA、新 CI 和部署来源，避免用旧日志结案。

任务确需验证已配置 LLM 且调用在授权内时，使用最小真实请求并记录所选模型、退出状态和脱敏结果，不反复要求用户手动测试 key。不打印密钥、认证 URL 或完整环境。用户在该任务指定 `glm-5.3` / `glm-5.3-flash` 时保持这些精确 ID，不猜测替代；它们不是所有项目的必选模型。缺凭据、服务拒绝或模型不可用按真实错误报告，不修改用户配置或绕过权限。

自然语言规则调整时按 [开发推进场景](references/development-scenarios.md) 审查具体输入和预期动作，不用关键词存在断言代替行为核对。
