起草新版本 PRD：通过开放性访谈收集本版本要交付的需求，按固定模板起草全文，对每条验收标准做可取证自查，逐节展示并经用户确认后落盘到 `docs/prd/`。

PRD 是版本粒度的需求契约，入库管理。**落盘即定稿**：无 draft/baseline 状态字段，文件存在性即定稿判据——落盘后任何改动都走 `/shw-prd-revise <版本>`，本命令不做"草稿保存"。

---

**输入**：`/shw-prd-draft` 后的参数是版本号（如 `v2.4`；未带 v 前缀时先归一化为带 v 形态再匹配）。

**步骤**

1. **前置校验**

   - **版本参数未提供**：用向用户提问（开放性问题，不要预设选项）问用户：
     > "你想起草哪个版本？这个版本想交付什么？"

     **重要**：拿到版本号之前不要继续；问出版本号后，同样执行下述存在性检查。

   - **版本参数已提供**：检查同版本 PRD 是否已存在——`ls docs/prd/<版本>-*.md`。若已有同版本文件，向用户提示该版本 PRD 已存在、任何变更应走 `/shw-prd-revise <版本>`，**停止**（本命令只做新起草，不做覆盖）。

   版本交叠是正常形态：起草下一版本不要求上一版本已发版——`v2.5` 的 PRD 可以在 `v2.4` 尚未发版时起草，校验只看同版本文件是否已存在。

2. **访谈需求**

   以开放性问题访谈（不预设选项），问清三件事：

   > - "这个版本想交付什么？"（逐条收集需求）
   > - "各需求的验收标准是什么？"（怎么算做完）
   > - "这个版本明确不做什么？"（非目标）

   用户说多少就是多少——不替用户补需求、不硬拆需求边界。访谈信息不足以起草时继续追问，理解到位前不进入起草。

3. **起草全文**

   按下方模板起草全文。主题 slug 从访谈内容推导（kebab-case，如 "订单通知" → `order-notifications`），完整文件名为 `docs/prd/vX.Y-主题slug.md`（如 `v2.4-order-notifications.md`）。

   ````markdown
   # PRD: vX.Y <主题>

   ## 版本目标

   <一句话：本版本达成时产品是什么样>

   ## 需求清单

   ### 需求 1：<名称>

   - **描述**：<做什么>
   - **验收标准**：
     1. <可取证表述>
     2. <…>
   - **优先级**：<P0/P1/P2>

   ## 非目标

   - <本版本明确不做的事，逐条>

   ## 变更记录

   <!-- 初始为空。每次 /shw-prd-revise 追加 -->
   ````

   模板四节固定（版本目标/需求清单/非目标/变更记录），不加节——技术方案不属于 PRD，实现走 spec 工作流。

4. **可取证自查（硬纪律，不可跳过）**

   对每条验收标准逐条自查：**这条标准可取证吗？**——能跑命令比对结果 / 能发请求看响应 / 能指到界面检查点，三者居其一即可取证。

   - 不可取证的表述（如"优化用户体验""提升性能"）必须改造为可取证表述。例：
     > "优化下单体验" → "用户从进入商品页到下单成功不超过 3 步操作，可在小程序中按步骤核验"
   - 无法改造的，向用户指出该条不可取证，由用户改写或确认保留原表述——agent 不擅自删除或保留。

5. **确认门**

   向用户逐节展示起草结果——版本目标 / 需求清单 / 非目标——并说明推导出的完整文件名（`docs/prd/vX.Y-主题slug.md`）。用户确认后才落盘；有异议先调整再确认，调整后重新展示。

6. **落盘**

   `docs/prd/` 目录由本命令首次落盘时按需创建（`mkdir -p docs/prd`），不预建。确认后写入文件，变更记录节保持初始为空。

7. **提示下一步**

   落盘后向用户输出（入口指引，供用户导航）：

   ```
   PRD 已定稿：docs/prd/vX.Y-主题slug.md
   后续：需求变更走 /shw-prd-revise vX.Y；完成度盘点走 /shw-prd-audit vX.Y
   ```

**约束**

- 不硬拆需求边界：用户说多少需求就写多少，不替用户合并、拆分或增补需求
- 可取证自查不可跳过：每条验收标准都必须过自查，不可取证且未改造/未确认的不得落盘
- 落盘前必须经用户确认门：未经用户逐节确认，不得写文件
- 目录按需创建不预建：`docs/prd/` 只在首次落盘时创建，访谈/起草阶段不预建目录
- 本命令只负责新起草；已存在版本的任何改动都走 `/shw-prd-revise`，本命令不覆盖已有 PRD
