盘点 PRD 完成度：逐条读指定模块（或全部模块）PRD 的验收标准，每条对照代码/测试现实独立取证后判定，产出核对报告（达成附证据 / 部分达成 / 未动）。PRD 是模块活文档，完成度不记账——PRD 里没有执行记录，完成度靠本命令现场取证得出（读取式，不是记录式）。

任何时候合法：执行中看进度、Sprint Review 核对、阶段性复盘交付差异。Sprint Review 场景按 Milestone 圈定盘点范围、逐 Issue 核对，配合 Demo 使用。与 /shw-prd-release 的边界：release（外包交付边界冻结）内嵌自己的 fresh audit（不采信历史盘点报告），本命令的报告不是冻结依据。

---

**输入**：`/shw-prd-audit` 后的参数是模块名（如 `订单`，对应 `docs/prd/订单.md`）；参数未提供时问用户盘点单个模块还是全量。

**步骤**

1. **定位盘点范围**

   - **参数有模块名**：定位 `docs/prd/<模块名>.md`（不存在 → 提示该模块 PRD 不存在、起草走 /shw-prd-draft，停止）。
   - **参数未提供**：列出 `docs/prd/` 下的模块文件（目录不存在则提示尚无任何 PRD、起草走 /shw-prd-draft），问用户盘点哪个模块还是全部模块全量盘点，**不自行挑选**。
   - **Sprint Review 场景**（用户说明按 Milestone 核对时）：经 gitea-mcp 列当前 Milestone 下的 Issue，以各 Issue 关联的 PRD 需求与验收 checklist 圈定盘点范围；Issue 只做范围线索，达成判定仍以现场取证为准。

2. **逐条独立取证**

   通读 PRD 的需求清单，逐条验收标准**独立取证**后判定——每条单独取证，不因同一需求的其他条目达成而搭车判定；`TC:` 标注的标准优先查同名测试的 **PR CI run 记录**对号（经 gitea-mcp 查门禁结论，不本地跑测试）。

   取证来源合法集合（超出此集合的来源不得作为判定依据；agent 本地不跑任何测试、不起服务）：

   | 取证来源 | 说明 |
   | --- | --- |
   | 现场跑命令 | 执行编译级/只读命令比对结果（不跑测试） |
   | 读代码 | 读到检查点（关键实现位置） |
   | CI run 记录 | `TC:` 对齐测试的 PR CI 结论（绿/红），经 gitea-mcp 查 |
   | 查 git log | 需求对应提交与 docs PR 合并记录 |
   | 查 gitea-mcp | 关联 Issue / PR 状态（**只读**，不改 label、不评论、不关单） |

3. **独立取证纪律（硬纪律）**

   - **基于当下事实取证**：不采信"应该做完了"的记忆，不采信既往盘点报告——既往报告只能当线索（提示去查哪里），判断必须现场重新取证
   - **证据必须出示**：宣布任何条目达成必须附证据（命令输出 / 响应 / 代码位置 / 用例红绿），禁止裸判
   - **目检不越界**：目检类标准（界面/体验）取证到代码级检查点为止，标注"待用户目检"，不得自行宣布通过——这类结论只有用户能下

4. **产出核对报告**

   逐条列出判定，报告**只在对话输出，不写任何文件**。格式示例（简短）：

   ````markdown
   # PRD 订单 完成度核对报告

   ## 需求 1：<名称>

   - 验收标准 1（TC: 分页翻页）：**达成**——证据：请求 `GET /api/orders?page=2` 返回 200 且数据与第 1 页无重复（响应片段粘贴于此）
   - 验收标准 2（TC: 分页边界）：**部分达成**——差距：分页已实现但第 2 页起 offset 计算错误返回空列表（代码位置：`xxx/service.go:88`）
   - 验收标准 3（TC: 翻页控件视觉）：**待用户目检**——代码级已确认翻页参数透传正确（`xxx/List.vue:42`），视觉表现需用户目检

   ## 需求 2：<名称>

   - 验收标准 1（TC: 订单取消）：**未动**——`git log` 无相关提交，gitea-mcp 查无对应 Issue/PR，代码无对应实现

   ## 汇总

   - 达成 X 条 / 部分达成 Y 条 / 未动 Z 条 / 待目检 N 条（共 M 条）
   - 待目检清单：需求 1 验收标准 3（翻页控件视觉）…
   ````

   部分达成必须写清差距是什么；未动也附取证说明（查了哪里、没有查到什么）。

**约束**

- **零写副作用**：不改 PRD、不改任何文件；报告只在对话输出，不落盘
- **gitea-mcp 只读**：查 Issue / Milestone / PR 状态可以，不改 label、不评论、不关单
- **不采信记忆与既往报告**：完成度判断只认当下现场取证，既往盘点报告只能当线索
- **目检不越界**：界面/体验类结论只能由用户下，agent 到代码级检查点后标注"待用户目检"
- **全量盘点不挑不漏**：遍历 `docs/prd/` 时跳过 README.md，其余模块逐个盘点，不自行挑选范围
- git 查询只读（`git log` 等），不执行任何 git 写操作
