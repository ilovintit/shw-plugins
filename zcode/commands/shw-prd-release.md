PRD 发版：对指定版本的 PRD 做一次 fresh audit——逐条重验验收标准、只认当下事实——全绿或经用户裁决后写入发版标记。发版 = 冻结契约：标记写入后该 PRD 不可再改，后续需求变更走新开 PRD。发版标记是单向墓碑，无任何移除流程。

本命令由用户手动执行，执行即发版意图——全绿时展示证据摘要后直接写入标记，不需二次确认（有差距时除外，见裁决分支）。

---

**输入**：`/shw-prd-release` 后的参数是版本号（如 `v2.3`；未带 v 前缀时先归一化为带 v 形态再匹配），对应 PRD 文件 `docs/prd/<版本号>-<主题slug>.md`。

**步骤**

1. **前置校验一：定位 PRD 文件**

   - **参数未提供**：问用户要发版哪个版本（可列出 `docs/prd/` 现有 PRD 供参考），不猜默认版本。
   - **参数有版本号**：用 glob 定位，不猜路径：

   ```bash
   ls docs/prd/<版本号>-*.md
   ```

   - 恰一个匹配 → 使用该文件，继续下一步
   - 零个匹配 → 提示该版本的 PRD 不存在，停止
   - 多个匹配 → 列出全部候选让用户指定一个，不自行挑选

2. **前置校验二：检测发版标记**

   ```bash
   grep -m1 '^> 已发版：' docs/prd/<PRD文件>
   ```

   - 无输出 → 未发版过，继续下一步
   - 有输出 → 该 PRD 已发版、契约已冻结，提示无需重复发版，停止

3. **fresh audit：逐条重验验收标准**

   通读 PRD 需求清单，逐条读验收标准，每条独立取证判定。取证来源（全程只读）：

   - 现场跑命令、比对输出
   - 发请求、看响应
   - 读代码、走到代码级检查点
   - 查 `git log`（只读查询）
   - 查 `.changes/archive/`
   - 查 `.roadmaps/`

   判定纪律：

   - **不采信上一次盘点报告**——上次盘点后状态可能已变（新 change 归档 / 某处被改坏），判据必须是当下事实，历史结论只能当线索
   - 宣布达成必须附证据（命令输出 / 响应 / 代码位置），禁止裸判
   - 目检类标准只走到代码级检查点，标注"待用户目检"，不自行宣布通过

4. **裁决**

   - **全绿**（可判定的验收标准全部达成，目检类均已到代码级检查点）→ 向用户展示每条证据摘要（待目检项单独列出供用户过目），然后直接进入第 5 步写入发版标记——写入动作以用户执行本命令为确认意图
   - **有差距**（存在未达成 / 部分达成）→ 逐条摆出差距事实（每条标注达成 / 部分达成 / 未动 + 证据），然后**显式询问用户是否仍要发版**——部分达成要不要发是业务决策，只摆事实不替用户决定：
     - 用户答"发" → 进入第 5 步写入发版标记（承诺与交付的差异以本次发版核对报告为准，PRD 契约不改写）
     - 用户答"不发" → 退出，不写标记，提示去补差距（差距的善后属于后续 PRD 或修复工作，本命令不管）

5. **写入发版标记，输出发版完成摘要**

   在 PRD 文件的标题行（`# PRD: ...`）正下方紧邻一行写入（YYYY-MM-DD 为当天日期）：

   ```markdown
   > 已发版：YYYY-MM-DD
   ```

   **写入即冻结生效**——这一行是本命令唯一的写动作，写入动作本身是冻结的生效点，不受"PRD 不可修改"纪律约束；此后该 PRD 不可再被修改（revise 会劝阻）。

   然后向用户输出发版完成摘要：发版文件 + 发版日期 + 逐条判定结果；若走了差距裁决，摘要中附差距清单。

**约束**

- fresh audit 不采信任何历史盘点报告——判据必须是当下事实，历史结论只能当线索
- 有差距必须显式询问用户是否仍要发版，不替用户决定；全绿也不跳过任何前置校验，按步骤走完
- 发版标记的格式与位置固定：`> 已发版：YYYY-MM-DD`，标题行正下方紧邻一行——不写别处、不改格式
- 发版标记是单向墓碑：写入后不因任何理由删除或改写，无移除流程
- 多文件匹配必须列出全部让用户指定，不猜
- 本命令全程只读，唯一写动作是发版标记写入该 PRD 文件本身；不修改、不创建其他任何文件
- 不执行任何 git 操作（`git log` 等只读查询允许）
