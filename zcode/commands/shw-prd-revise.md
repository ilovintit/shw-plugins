修订未发版（契约态）PRD：先定位 PRD 文件并检测发版标记，再起草变更摘要、经用户审核确认后更新文档，最后在变更记录节留痕。

与 /shw-prd-draft 的边界：draft 管下一版本 PRD 的起草；本命令管**未发版** PRD 的修订变更。已发版（文档头部有 `> 已发版：YYYY-MM-DD` 引用行）即冻结，本命令一律劝阻。

---

**输入**：`/shw-prd-revise` 后的参数是版本号（如 `v2.3`；未带 v 前缀时先归一化为带 v 形态再匹配）。PRD 是版本粒度的需求契约，存放 `docs/prd/vX.Y-主题slug.md`；落盘即定稿，发版后冻结。

**步骤**

1. **定位 PRD 文件**

   - **参数未提供**：问用户要修订哪个版本（可列出 `docs/prd/` 现有 PRD 供参考），不猜默认版本。
   - **参数有版本号**：用 glob 定位（版本号后紧跟 `-`，所以 `v2.3-*` 不会误匹配 `v2.30-x.md`）：

   ```bash
   ls docs/prd/<版本号>-*.md
   ```

   - 恰一个 → 用之，继续下一步
   - 零个 → 向用户提示该版本 PRD 不存在、起草走 `/shw-prd-draft`，停止
   - 多个 → 列出全部让用户指定，**不猜**

2. **发版标记检测**

   ```bash
   grep -m1 '^> 已发版：' docs/prd/<文件>
   ```

   - 有输出 = 已发版冻结 → 劝阻并停止，向用户提示："该 PRD 已发版冻结，需求变更应新开 PRD，新需求走 /shw-prd-draft 起草下一版本"
   - 无输出 = 契约态，继续

   发版标记是墓碑单向的：本命令不提供任何移除/修改发版标记的路径，标记写入后 PRD 不可再改。

3. **读 PRD 全文，理解变更意图**

   通读 PRD 全文，结合用户描述的变更意图定位受影响的需求节与验收标准。意图不明确或与 PRD 现状有出入时，先向用户提问澄清，理解一致后再继续。

4. **起草变更摘要**

   起草变更摘要并向用户展示，须包含：

   - **改什么**：触及 PRD 的哪些节、哪些需求
   - **为什么**：变更的动机与背景
   - **影响哪些需求与验收标准**：逐条列出——原文表述 → 改后表述（新增/修改/删除分别标注）

5. **审核门（硬门）**

   向用户展示变更摘要，**用户确认后才修改文档**；用户未确认前文档不变；用户有异议则调整摘要后再次确认。禁止跳过审核门直接改文档。

6. **执行修改**

   按确认的摘要更新 PRD 对应节。若变更涉及新增验收标准，同样执行可取证纪律：验收标准必须可取证——能跑命令比对 / 发请求看响应 / 指到界面检查点；不可取证的表述先改造为可取证写法，无法改造的提请用户裁决。

7. **变更记录留痕**

   在 PRD 的变更记录节追加条目（无该节则在文末创建），**不许静默修改**：

   ````markdown
   ### YYYY-MM-DD <一句话摘要>

   - 改动：<改了哪些需求/验收标准>
   - 经用户确认
   ````

   完成后向用户输出：改了哪些节、留痕条目落在何处。

**约束**

- **用户未确认不改文档**：审核门是硬门，摘要未获用户确认前 PRD 文件保持原样
- **变更记录必留痕**：任何对 PRD 的修改都必须在变更记录节追加条目，不许静默修改
- **已发版必劝阻**：检测到发版标记一律劝阻并停止，提示新开 PRD；发版标记为单向墓碑，不提供移除/修改标记的路径
- **多文件匹配必让用户选**：glob 命中多个文件时列出全部让用户指定，不猜
