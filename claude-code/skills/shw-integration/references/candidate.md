# 集成来源、独立测试快照与制品复用

## dev→main 集成来源

集成 PR 记录仓库、来源 dev SHA、PR HEAD、main 基点、预合并 tree、Issue 范围和授权。正常合并前回读这些身份；来源或冲突解决变化时更新记录。冲突解决属于本次集成内容，未体验、未验收如实记录，不能把测试结果或人工验收作为默认集成前置门禁。

合并后记录实际 main SHA、父提交和 tree，核对实际范围与已审来源。未知来源、未授权范围或不可证明的制品身份应停止相应动作；未运行测试本身不阻挡已授权集成、发布或部署。dev→main 不运行单元、API、E2E、VRT、冒烟或回归。

## 独立测试快照

仅用户明确主动要求时，从指定业务提交建立独立 `test` 分支快照。记录请求范围、test HEAD/tree、业务来源 SHA、目标 revision/digest、测试配置、环境、fixture 和基线 revision。push 到 test 不是测试请求；测试 workflow 仅 `workflow_dispatch` 并守卫 `refs/heads/test`，执行前核对本次用户请求。读取或访问 test/生产环境仍需对应授权，不能由测试请求推导额外凭据或权限。

测试配置、fixture、目标或快照变化使旧报告失效；重新运行仍需处于本次主动请求范围，不自动追踪或重跑。test 快照与结果不是发布来源，不默认 test→main，不自动合并测试基线到业务分支。

`candidate-policy.mjs` 仅处理源码/构建候选：已授权范围、Issue/提交祖先关系、候选漂移和构建输入身份；人工体验记录可选。test/基线不参与 fingerprint、判断或晋升，独立测试与基线另存记录。调用方采集真实证据，不通过模块取得测试、合并或发布权限。

## 按需测试差异与基线

| 分类 | 证据 | 本次测试范围内的处理 |
| --- | --- | --- |
| 环境故障 | 服务、认证、fixture、浏览器或依赖异常 | 记录 execution-error；按请求修复或报告缺项，不写基线 |
| 已确认预期变化 | 逐项映射 Issue/AC 与用户裁决或实际体验 | 明确更新范围和理由，审查对应断言或基线 |
| 疑似回归 | 与批准范围无关的行为差异或契约失败 | 保留证据并调查；业务修复另按授权交付 |
| 未知 | 原因或预期对应关系不清 | 保留差异，不全量接受快照 |

不删除断言、提高阈值、缩小选择器或回滚正确实现来迎合旧测试。初始基线记录来源、范围、用户确认与实际执行状态；unbaselined、partial 或空选择不能写成全部通过。需要复跑时在主动测试请求范围内手动执行，不附加到发布或部署链路。

基线只在独立 test 分支或明确授权的基线维护区更新。基线晋升须单独授权并核对实际来源，不随着 main 合并或发布自动晋升；失败、未运行或无基线均不阻挡已授权发布。

## 制品来源与复用

dev SHA 与 main SHA 分别记录。构建记录包含 build_source_sha、source_tree、构建配置/锁文件/依赖/工具链/参数/构建期变量指纹、artifact_digest 与对应 main SHA。仅来源和完整构建输入等价时复用 digest；否则完成必要构建生成新的可追溯制品。发布选择授权的 main 提交/制品，test 快照和测试报告不替代发布来源，tag 不触发测试。
