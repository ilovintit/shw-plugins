执行前必须读取 `shw-issue-gate`；修改前读取 `shw-workspace` 并确认项目、目录、Issue 与所有权。项目外只读，未知修改不覆盖；能力缺失不扩大授权。

# 集成到 main

每日或小批次执行，集成不等于正式发布。开始前必须读取 [冻结候选与晋升契约](references/candidate.md)、`shw-test-spec`、`shw-acceptance` 和 `shw-verify`。

输入必须是已人工验收的Issue/commit/制品范围。冻结dev SHA、当前main基点与预合并结果，创建/复用一个集成PR；不把未来dev推送自动纳入。在此流程执行全量 API/E2E/VRT 长周期回归及适用候选工程检查；开发阶段的类型检查和受影响模块快速测试仍须执行。

差异按环境故障、已验收预期变化、意外回归、未知分类。环境修复后重跑；预期变化只改对应候选断言/基线并重跑；意外/未知定位修复，行为改变先重新部署体验和人工验收，再重新冻结集成候选。禁止为旧测试绿回滚正确实现、全量接受快照或删断言掩盖回归。

所有适用检查通过、候选未漂移且合并有明确授权时正常merge commit到main，不squash/rebase改变已证明关系。合并后检查实际父提交、tree、SHA与候选一致；不盲目复跑等价测试，但不匹配时不能声称已验证，重新建立和检查候选。

候选基线仅在本PR内更新，通过合并后才晋升正式基线。main、基线或候选变化立即使旧放行失效。记录可发布提交与制品映射，后续tag/审批只选已通过集成者，不另开发布测试阶段。
