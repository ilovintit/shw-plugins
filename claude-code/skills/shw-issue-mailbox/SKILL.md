**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

# 跨会话冲突去 Issue 上沟通

多个会话（可能分属不同 Agent 工具）同时交付不同 Issue 时会撞上同一份共享资源。会话之间没有共享内存，也无法互相唤醒，**唯一可靠的通道是 Gitea Issue 评论**：持久、带时间戳、三端都能读写、不要求双方同时在线。

**发现冲突时自己去沟通，不要停下来让用户转达。**

- **先到先得**：对方先动的，当前会话避让——改自己的文件名、rebase 到最新 dev、把改动叠在对方之上。能自己避让完就做完，不用惊动任何人。
- **留言**：评论发在**对方的 Issue** 下，说清楚冲突是什么、我打算怎么做、需要对方确认什么、我当前停在哪。不新建协调用 Issue，不猜着发到不确定的 Issue 号。
- **不阻塞**：留言后继续做不依赖答复的部分；开 PR 前顺手看一眼自己 Issue 下有没有别人问而自己没回的。

## 边界

- 不得跨 Issue 修改对方的分支、代码或迁移文件，只能留言。这违反 Issue:分支:PR = 1:1:1。
- 避让解决不了的分歧（同一字段两种含义、两种互斥方向）交用户，把双方方案、理由和推荐整理好一次性给出，不自己拍板也不互相僵持。

Gitea 读写口径见 `shw-gitea-flow`，PR/CI 读取见 `shw-gitea-ci`。任何 Gitea 写操作完成后重新读取验证。
