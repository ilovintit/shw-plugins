# 开发推进场景审查（#452）

这些是交付审查用的输入/预期行为，不是固定句式测试；规则文字或构建通过不能证明真实服务、业务项目或宿主已验收。

| 场景 | 应观察的行为 |
| --- | --- |
| 小模块 API 修改准备合入 dev | 执行必要构建并记录准确来源；不运行测试。仅用户主动要求时转独立 test 分支手动执行，不以未测试阻挡已授权交付。 |
| 项目 dev 原有自动迁移 | 核对该项目授权后保持原流程；项目规定用户手动迁移时仍由用户执行，不套用其他项目集群/命名空间。 |
| 当前检查绿但读不到保护详情 | 在合并授权内尝试正常入口；服务端拒绝就报告原因，不 force；skipped 不当作绿。 |
| PR 修改 workflow 尚未进入 dev | 根据当前 Gitea 版本、事件和 run 来源辨别 head/base，再判断实际执行内容。 |
| CLI 已返回会话 ID但未退出 | 保留 cwd、正确结束输入并等待退出；不把启动成功当请求成功。 |
| 已配置 LLM，任务给出精确模型 ID | 最小真实调用；不猜模型，不回显 key，不以别的模型成功替代。 |
| 新产品还没有表 | 根据 PRD 设计模型与迁移；不要求用户先造数据库，不直接迁移共享库。 |
| GOPROXY 可能含认证信息 | 采集源头只报告存在性或允许字段，异常也不输出原始值。 |
| 三个后端地址已确认 | 在授权运维配置预填地址，只输入对应秘密；公共模板仍用示例，DBX 使用 Web 密码字段。 |
| 本地与云都有同目标工具 | 选择可用本地入口；认证/写入拒绝不静默改云重试，未知结果先回读。 |
| 多项目中一个阻塞 | 已授权的独立任务继续，各守工作区和部署权限；不自动扩大范围或派工。 |
