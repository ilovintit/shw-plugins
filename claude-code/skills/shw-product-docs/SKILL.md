**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

## 模式前置

本 Skill 不是所有项目的默认约束。先读取仓库根 `.shw/project.yaml` 的模式：无标识时不主动应用；`issue-main` 只保留 Issue 分支→main 的轻量闭环；`issue-dev` 只保留 Issue 分支→dev→main 的轻量闭环；只有 `managed` 才应用本 Skill 中的业务项目目录、分支、测试、发布、部署或公司规范要求。模式定义见 `shw-issue-gate/project-mode.md`。

# 文档与实际实现

## 轻量 PRD

- 唯一产品级入口 `docs/prd/product.md`，历史通过 Git/PR/tag 保存，不按端或版本复制竞争 PRD。
- 记录已确认目标、当前范围/非目标、相关角色权限、关键业务规则、主流程与可观察验收结果；当前功能涉及状态/异常、数据口径时必须说明。
- 完成标准是足够支撑当前小版本开工，不预写全部未来功能或逐字段视觉细节。待裁决项与已确认结论分开；只阻止依赖它的工作，不阻止其他已明确功能。
- 文档由 Agent 维护，复用已有裁决。用户主要体验实际产品并作业务决定，布局、间距、文案和操作顺序通过真实前端迭代。

## 增量技术文档

- 整体入口 `docs/architecture/index.md` 保留稳定系统边界、技术栈、开发环境与必要约束。
- 按当前迭代补齐数据、API/事件、权限、状态、兼容/迁移、测试和部署方案；复杂时才拆 clients/services/domains/data/apis/security/testing/deployment，所有子文档由入口索引。
- 当前核心契约必须明确，未来方案不要求一次定完；跨文档契约只有一个权威定义位置。
- Kubernetes 应用说明项目声明、Fleet、镜像与回滚；插件/库/CLI 说明制品、调用/安装与回退。未实测范围按事实记录。

## 实际体验入口

首个可体验功能前打通最小可运行工程、配置、开发 API/前端、受控数据与部署/调试链，后续复用。实际前端按公司前端规范及项目已发布组件实现，浏览器/开发者工具/真机承担各端体验，不维护另一套必需 HTML 原型或 `docs/design/` 目录。

每个可体验功能就绪后提供实际入口、源码/制品/部署标识、角色/数据、步骤、预期和已知限制，等待用户反馈后修正再继续。仅有页面或显式 mock 时标明未联调与可体验范围，不将其当作后端、权限、数据或完整业务验收。

## 文档随反馈同步

1. 布局、间距、提示与操作体验直接修改实际前端并记录反馈；不为每次视觉微调重写 PRD 或创建独立产品文档 PR。
2. 权限、状态、数据口径、金额规则等业务变化由用户裁决后更新 PRD；数据/API/服务或部署契约变化同时更新技术文档。
3. 文档与当前功能实现进入同一 Issue/工作区/分支/PR；独立产品定义请求仍可交付文档 PR，不强制拆成多份文档生命周期。
4. 将文档一致性、设计与实现自审融入需求、方案和交付，聚焦当前变更及其受影响契约；不设独立全产品综合审查阶段。
5. Agent 可在已授权开发请求中维护小版本、Issue 和当前体验步骤，不要求用户逐个调用规划命令；真实产品/版本裁决仍由用户决定。

存量 `docs/design/`、`ui-design.md` 和有效页面只作历史参考；升级盘点并保留内容与来源，解除必需生成/验收/持续同步要求，不自动删除、不据旧原型推翻已确认 PRD 或实际实现。
