**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

## 模式前置

本 Skill 不是所有项目的默认约束。先读取仓库根 `.shw/project.yaml` 的模式：无标识时不主动应用；`issue-main` 只保留 Issue 分支→main 的轻量闭环；`issue-dev` 只保留 Issue 分支→dev→main 的轻量闭环；只有 `managed` 才应用本 Skill 中的业务项目目录、分支、测试、发布、部署或公司规范要求。模式定义见 `shw-issue-gate/project-mode.md`。

# 体验、反馈与最终验收

## 持续体验

人工体验不需要独立 accept 命令。每个可体验功能在 dev/实际端就绪后，由 Agent 提供入口、源码/制品或部署标识、角色/数据、步骤、预期与已知限制；记录待反馈并等待用户回复，再修正或继续下一项。

浏览器检查、CI、上传或部署健康分别证明相应事实；仅有 mock/未联调页面时明确可体验范围，不冒充完整业务、真实权限或数据验收。非体验维护项按可验证调用/制品处理，不要求虚构页面验收。

## 反馈与修正

- 布局、间距、提示和操作体验：直接修改实际前端并保留反馈，不为每次微调启动文档审查阶段。
- 与已确认 PRD/AC 不符：Bug，先搜索重复；未合并时可在原 Issue/PR 修正，已合并后建立关联小修正 Issue/PR并重新验证。
- 新能力或业务规则变化：用户裁决后增量更新 PRD 与必要技术方案，在当前功能或后续关联 Issue 中落实，不暗中扩大 Version。
- 当前版本承诺范围的反馈挂当前 Milestone；历史已关闭版本的问题进入新维护 Version 或 Hotfix，不回开历史版本。

用户确认满意或明确授权继续后再推进下一功能；只说继续允许推进，不记为验收通过。明确授权连续开发可跳过等待，记录未体验范围。反馈失败先修正或取得延期裁决，不能以无回复、时间过去或工程合并推定通过。

## 发布候选确认

范围全部交付后汇总逐功能反馈与修正、当前候选源码/环境、已确认/未确认范围，复核跨功能流程和受后续改动影响的已确认行为。已有有效反馈可复用，不机械要求从头重复全部体验；`release` 使用真实的 dev 候选确认事实决定放行。

## 最终人工验收

发布/部署后用户对不可变 main commit/tag、制品或 deployment revision 作最终人工验收，记录时间、范围、步骤、结果和证据；按产品形态验证真实依赖、关键路径与生产观察。阻断问题必须清零，非阻断项由用户确定归属后才关闭 Milestone。

main 合并、发布/部署健康与开发反馈都不替代最终验收。`baseline` 仅在最终确认后引用不可变 source 与明确范围，以独立维护 Issue/PR固化回归；缺基线不推翻已发生验收，但记录未受保护范围。

Agent 维护事实与载体，不替用户宣告体验满意或验收通过。仓库已确认的分发/关闭例外继续按项目 Agent 规范执行。
