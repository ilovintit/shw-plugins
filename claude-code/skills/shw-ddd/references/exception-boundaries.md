# 异常分层规则

每层有自己的异常目录，异常类型按层划分（三分类语义与映射规则见公司 lib 仓库错误处理文档，**shw-lib-docs** 指路）。异常**从内层直接向上冒泡**，各层不做逐层捕获转换：

| 层 | 异常类型 | 语义 | 全局处理器映射 |
|----|---------|------|--------------|
| Domain | 业务规则被违反 | "库存不足"、"状态不允许此操作" | HTTP 422，日志 Warning |
| Application | 业务流程异常 | "资源不存在"、"操作无权限" | HTTP 200，日志 Info |
| Infrastructure | 技术故障 | "DB 连接失败"、"第三方超时" | HTTP 500，日志 Error |

**规则**：异常由抛出点直接冒泡，由**全局异常处理器**统一捕获分发——按异常类型映射 HTTP 状态码/业务码/日志级别，装配统一响应。各层不写 try-catch 逐层捕获转换，Controller / UseCase 无需包裹异常处理。异常类型的具体命名（后缀、错误码体系）与全局处理器的具体落地由各语言 conventions 决定。
