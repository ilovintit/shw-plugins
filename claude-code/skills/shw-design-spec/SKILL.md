# 直接维护 HTML 原型

## 规范与执行者

- 当前宿主 Agent直接写文件、启动本项目预览并操作浏览器，不派发给外部设计平台或另一层CLI，不轮询外部生成任务。继续使用当前宿主已选择的模型，不代用户切换模型。
- 先读PRD、`shw-frontend-stack`、`shw-frontend-spec-common`及对应端规范。业务角色×端形态来自PRD，已知的产品形态不重复询问；只有真实缺失/冲突的产品决定才回用户。
- 组件、主题和交互以公司规范、项目既有组件库及已确认页面为准，不加入第三方品牌设计系统、随机配色或另一套交互规则。原型HTML是验收表达，不改变生产的pure-admin/Element Plus、Taro/Shw或Nuxt选型。
- 优先引用当前项目已有、浏览器可运行的组件构建和样式。纯HTML不能直接运行Taro组件标签：缺少可用的H5构建时，按已验证组件文档和主题变量做标注了组件映射的原型表达，不复制库源码、不把仿真声称为真实组件或原生端验收。正式实现仍必须使用公司组件。

## 文件组织与持续修改

1. 读取现有 `docs/design/`、PRD和已确认设计；记录本次Git基线及页面/依赖清单。一个业务项目只有一套原型，按真实角色与端长期维护，Issue只隔离Git变更，不新建一套原型。
2. 创建或整理目录前读取 [目录与依赖约定](references/structure.md)。产品 `index.html` 负责入口索引，端内页面用业务语义命名，样式、交互、素材与示例数据职责分离；简单页面不强制拆出空目录。
3. 原地增量修改，保留有效页面、字段、权限、状态、布局与资产。旧路径需要调整时同时修复所有入口和资源引用，不只拿PRD从零重做、不清空整个目录。
4. 技术选择遵循实际浏览器能力：可独立打开的页面用相对资源；需要模块/请求时记录本项目HTTP预览入口。项目存在 `./dev` 时所有启动/构建命令经它执行，新增端口按 `shw-port-manager` 登记；不为了原型另建生产服务。

## 交互与模拟边界

- 覆盖公司规范的详情加载、提交防重、未保存关闭确认、成功刷新、失败保留输入、删除确认、分页/筛选联动和响应式；不能用只有静态外观的图片替代交互。
- 未接真实后端时，使用显式命名的mock adapter和fixture，标为“原型模拟，未联调”。详情/编辑只传ID，由独立detail函数取得完整详情fixture并表现loading/error；禁止把列表行直接当详情，即使是原型也保留这一契约。请求成功、失败、空态等应能在预览中明确触发。
- 真实与模拟数据来源分开；原型默认不连接生产写接口。纯展示摘要预览的例外只按通用前端规范和已确认产品规则使用。

## 浏览器验收与完成

- 直接打开实际生成的页面，核对索引/导航、各端关键流程、桌面/移动视口、表单/弹窗状态、键盘焦点、控制台与资源加载。将用户反馈改到同一套文件，重新预览，直到用户明确接受。
- 静态结构检查不证明高保真或交互正确。浏览器能力不可用时如实标记未实测，不用新增文字关键词断言替代验收；业务截图/VRT只放该业务项目允许的位置，不搬进插件仓库。
- 验收前不清理旧版；用户接受后仅删除已明确替代的文件，再检查所有引用与关键流程。记录验收commit、入口、视口、模拟范围和未实测边界；继续同一draft产品PR的architecture/product-review，零阻断才合入dev。
- 命令或预览进程卡住时查看退出状态、错误输出与实际文件变化。相同失败重试一次仍无新证据则停止该步骤，报告具体阻塞和已完成文件；不以反复无变化轮询充当进展，也不擅自更换设计平台重做。

历史外部设计制品先使用已有仓库文件；若完整内容只在外部工具内，由用户提供一次完整导出后迁入上述目录。保留仍有效的内容和来源记录，不要求旧项目ID、登录、模型配置或外部运行状态；不自动操作或删除外部项目及用户配置。
