**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

## 模式前置

本 Skill 不是所有项目的默认约束。先读取仓库根 `.shw/project.yaml` 的模式：无标识时不主动应用；`issue-main` 只保留 Issue 分支→main 的轻量闭环；`issue-dev` 只保留 Issue 分支→dev→main 的轻量闭环；只有 `managed` 才应用本 Skill 中的业务项目目录、分支、测试、发布、部署或公司规范要求。模式定义见 `shw-issue-gate/project-mode.md`。

# 当前迭代的设计审查

在必要技术方案与交付自审中内部执行，不设独立产品综合审查阶段。完整读取本次变更及受影响契约，按适用范围检查：

1. 每项能力回指已确认 PRD 目标或非功能要求，不暗中扩需求。
2. 当前真实客户端的字段、动作、权限、状态、异常和跨端旅程有必要的数据/API/客户端实现支撑；视觉与可用性在实际端反馈迭代。
3. 当前数据约束、生命周期、迁移、API 鉴权、幂等、错误、分页、并发与兼容足够明确。
4. 受影响外部依赖、超时/重试、部分成功、回滚与可观测性有可执行方案。
5. 必要工程检查、当前体验步骤和目标环境匹配，未联调/未实测部分如实标明。
6. 按产品形态审查：Kubernetes 应用核对项目声明、Fleet、镜像、健康/回滚；插件/库/CLI 核对制品分发、调用/安装与回退。
7. 项目 Agent 不使用 Ansible、不持有 kubeconfig/Token、不直接写 K8s；集群查询只经统一只读 MCP。

输出阻断、需用户裁决与可改进项。确定性问题直接修正；业务语义、公开契约与重要权衡由用户裁决后写回权威文档。仅因未来功能、原型或全产品技术文档未完整，不阻止当前已明确的小功能开工。
