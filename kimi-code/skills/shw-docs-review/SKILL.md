**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

## 模式前置

本 Skill 不是所有项目的默认约束。先读取仓库根 `.shw/project.yaml` 的模式：无标识时不主动应用；`issue-main` 只保留 Issue 分支→main 的轻量闭环；`issue-dev` 只保留 Issue 分支→dev→main 的轻量闭环；只有 `managed` 才应用本 Skill 中的业务项目目录、分支、测试、发布、部署或公司规范要求。模式定义见 `shw-issue-gate/project-mode.md`。

# 文档一致性自审

审查当前变更、受影响文档与实现，内部执行，不要求用户另行发起综合审查。

- 用户裁决/反馈和 Issue → PRD/技术文档/实现：不得遗漏、弱化或改变当前承诺。
- 文档 → 裁决/代码证据：不添加无来源范围，不把假设、未来能力或未联调页面写成已实现。
- PRD ↔ 技术方案：当前业务规则、数据口径、权限、状态、接口与部署可落地；无需先完成全产品文档或独立原型。
- 文档 ↔ 实际实现：布局和交互由真实端体验验证；业务或技术契约变化必须同步权威文档，纯视觉微调不强制重写 PRD。
- 验收记录 ↔ 实际目标：入口、源码/制品/部署 revision、步骤、用户反馈及已确认/未确认范围可追溯；CI 或页面存在不等于用户通过。
- 索引、链接、术语与权威定义一致；旧原型仅作历史资料，不能继续作为开工、验收或文档同步前置。

完整读取本次 diff、改动文件和受影响契约，结果分阻断、需裁决与改进；确定性问题同分支修复后复审。未决未来范围只阻止依赖它的工作，不制造全产品文档完备门槛。
