# 重型测试无人值守巡检与修复

治"重型测试没人跑"：E2E / VRT / 性能 / 全量集成测试跑得慢、占资源，日常开发流转中被切成轻量验证，重型层长期缺乏执行，回归悄悄累积。本 skill 做**重型测试的夜间无人值守巡检+修复**——凌晨闲时全量执行、失败分类处置、真 bug 直接修（红绿纪律）。与 spec 审计 skill 是姊妹模式（同为无人值守定时巡检），关键差异：spec 审计绝不改代码，本 skill 的任务就是修代码修 bug，授权边界靠四级分类+禁改断言红线约束。

## 触发场景

- agent 定时任务（cron / 闲时 / 凌晨定时）跑 E2E / VRT / 重型测试并修复失败
- 用户手动要求"全量重型验证 / 把 E2E 全跑一遍 / 巡检一遍测试"
- 日常 change 流转切出的重型层验证（日常只跑轻量测试，重型层由本 skill 承接）

## 巡检工作流程

### 1. 入口自动发现

不依赖人工告知，从三处自动发现重型测试入口：

- **package.json（或等价构建清单）scripts**：按命名模式识别——`e2e` / `vrt` / `snapshot` / `visual` / `playwright` / `cypress` / `perf` / `benchmark` / `integration:full` 等
- **E2E / VRT 框架配置文件**：`playwright.config.*` / `cypress.config.*` / 框架专属快照目录约定（如 `__screenshots__` / `snapshots/`）等
- **项目 AGENTS.md / 元文档声明的测试命令**：文档里写明的重型验证命令

发现的入口清单进报告。**发现不了任何重型入口时，报告"本项目无重型测试"并正常结束（非错误、非告警）**——这是合法终态。

### 2. 全量执行

逐个跑全部发现的入口，记录每个入口的通过 / 失败 / 无法执行（如环境缺依赖）结果。单个入口失败不中断其余入口——先全量收集，再统一处置。

### 3. 失败四级分类处置

**排查顺序固定：先排环境、再复现、再定性。** 每个失败先排除环境因素，再尝试稳定复现，最后才定性分类：

- **① 真 bug**（可稳定复现的断言失败）→ **直接修**。红绿纪律：
  1. 先写复现测试，跑一遍确认失败（**红**）
  2. 修产品代码，再跑到通过（**绿**）
  3. **禁止改测试断言迁就现状**——断言是事实源，改断言等于销毁检测能力
- **② 环境问题**（端口占用 / 依赖缺失 / 服务未起 / 数据库不可用等）→ 只修环境重跑。环境处置**不算 bug 修复 commit**（见落盘纪律的前缀区分）
- **③ 测试过时 / 需求疑似变化**（测试描述的行为与当前合理实现冲突，但判不了谁对谁错）→ 不修产品代码也不改测试，报告留档待人工裁决
- **④ 修不动 / 影响面大**（需要设计决策 / 跨模块改动 / 修了风险大于收益）→ 停止修复，报告留档说明卡点

只有①有权改产品代码；③④是无人值守的权限边界——宁可漏修一夜，不做无人背书的重大改动。

### 4. VRT 基线保守策略

截图 diff **一律不自动更新基线**。理由：无人值守下无法可靠区分"回归"与"预期 UI 变化"（最近有人改了 UI 但基线没刷），错误基线的危害大于漏检一天——错基线会把真实回归永久洗白。

处置方式：报告的"VRT 基线待裁决"区附：

- diff 清单（哪些用例 / 哪些截图 / diff 幅度摘要）
- 手动基线更新命令示例（按项目实际 VRT 工具给出对应命令）

由用户人工裁决后手动更新。

## 修复落盘纪律（选择性暂存）

- **无脏工作区熔断**：不做事前工作区检查。roadmap 探索等合法流程可能留下未提交改动，巡检不因此终止；改用选择性暂存控制落盘范围
- **每个 bug 修复独立本地 commit**（**绝不 push**）。只 `git add <该修复实际触碰的文件显式路径>`，**禁止 `git add -A` / `git add .`**
- commit message 前缀区分：
  - `fix(e2e-audit): …` —— 产品代码修复（①类，附红绿证据）
  - `chore(e2e-audit): …` —— 环境处置等非产品修复（②类，不算 bug 修复 commit）
- 报告含 **commit → 修复映射**，让每个修复可定向 revert
- **残留风险明示**：若修复触碰的文件恰与用户未提交改动同文件，选择性暂存会把用户改动一并卷入该 commit。报告尾部必须提示这一风险，由用户复核

## 报告形态

报告**只在会话内输出**：不形成文件、不进 git、无任何持久化产物。五区结构：

1. **修复明细**：每个①类修复 + 对应 commit + 红绿证据（复现测试失败输出 → 修复后通过输出）
2. **环境问题处置**：②类问题 + 处置动作 + 重跑结果 + 对应 chore commit
3. **VRT 基线待裁决**：截图 diff 清单 + 手动基线更新命令示例
4. **待人工判断项**：③④类问题 + 判不了 / 修不动的卡点说明
5. **巡检健康度概览**：执行入口数 / 通过 / 失败 / 各级分类计数（①②③④各多少），供人工跨轮比对趋势

## 定时任务 prompt 示例

本 skill 支持无人值守定时执行。配置方式：**用户在自己 agent 工具的定时任务功能中手动粘贴以下 prompt 文案**——插件侧不做任何自动注册。锚点建议选"闲时"而非精确凌晨：宿主机凌晨可能处于休眠状态，定时任务跑不起来。

```
加载 shw-e2e-vrt-audit skill，对本仓库执行一次重型测试巡检：按 skill 工作流程完整执行
（入口自动发现 → 全量执行 → 失败四级分类处置 → 选择性暂存落盘），最后输出五区报告。
全程无人值守：不问问题、不等确认；真 bug 按红绿纪律修复并独立本地 commit（绝不 push）；
VRT 基线一律不自动更新，留待人工裁决。
```

## 约束

- **无人值守自包含**：不问问题、不等确认、不等任何用户输入
- **排查顺序固定**：先排环境、再复现、再定性
- **只有①类有权改产品代码**，且必须红绿纪律（先复现红、后修复绿）；**禁止改测试断言迁就现状**
- **③④只留档不修**：测试过时与修不动是人工裁决区，不代做决定
- **VRT 基线一律不自动更新**：diff 只报告，基线更新由用户手动执行
- **本地 commit 绝不 push**：`fix(e2e-audit):` / `chore(e2e-audit):` 前缀区分，选择性暂存（显式路径 add），禁止 `git add -A` / `git add .`
- **报告只在会话内**：不落文件、不进 git、无持久化产物
- **工具无关**：不绑定任何单一 agent 工具；定时任务由用户在自己工具的定时任务功能中手动配置
