**项目外只读**：仅可修改当前项目已确认的工作目录（交付时为当前 Issue worktree）；外部路径禁止直接或间接写入。需要修改时先停止，报告路径、原因和拟修改内容，请用户介入并交其他获授权 Agent 或用户手动处理。完整边界及有限运行例外见 `shw-issue-gate`，执行前必须读取。

# TDD：只对适用工程行为测试先行

## 模式前置

本 Skill 不是所有项目的默认约束。先读取仓库根 `.shw/project.yaml` 的模式：无标识时不主动应用；`issue-main` 只保留 Issue 分支→main 的轻量闭环；`issue-dev` 只保留 Issue 分支→dev→main 的轻量闭环；只有 `managed` 才应用本 Skill 中的业务项目目录、分支、测试、发布、部署或公司规范要求。模式定义见 `shw-issue-gate/project-mode.md`。

先判断本 Issue 是否有适合自动化且能在实现前稳定表达的工程行为，例如纯函数、协议、解析、权限边界、安全规则或插件运行时契约。API/E2E/VRT 业务回归基线遵循 `shw-test-spec`，只在最终人工验收后维护，不参与本 Skill 的 RED/GREEN。

1. 从 Issue AC 取得稳定工程断言。先写能证明目标行为缺失的最小测试，并自审失败原因。
2. 将测试提交到本 Issue 分支，创建或更新同一草稿 PR；推送并等待 CI 红色结果。必须读日志确认红在目标行为，而不是编译、语法、网络或测试环境错误。
3. 保存红色 head SHA、run/job 与失败断言，再写满足 AC 的最小实现。
4. 本地默认只做build/typecheck；开发中确有必要时经项目指定入口做明确范围的小单测并记录，不能代替CI；推送实现后确认同一 PR 的最新 HEAD 所需 CI 全绿，再重构并重新验证。
5. 适用工程测试和实现留在同一个 Issue/分支/PR；只有交付完成才移除草稿状态并合并。

已有可靠复现测试可直接使用其对应 CI 失败证据。纯文档、prompt/配置说明、无法在实现前稳定表达的集成行为或不改变行为的修正不制造假红测试，应记录不适用原因，以人工 AC、内容审查、构建、类型检查和适用契约检查取证。不得为了保留 TDD 形式提前编写 API/E2E/VRT、截图或自动化映射。

开发中必要的本地快速单测遵守项目入口、明确范围和宿主规则，记录环境和结果；本地结果不能替代合并所需的 PR CI。若 AC 无法表达，先收敛契约，不能用大量 mock 自证。
