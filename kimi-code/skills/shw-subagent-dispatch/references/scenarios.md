# 派发行为场景

维护技能和升级插件时审查以下场景的实际决策；不要用固定文案关键词断言替代行为审查。

| 场景 | 应有行为 |
| --- | --- |
| 开发一个 Issue，用户未逐次点名子代理，存在独立调查与实现 | 开发入口主动加载派发指导；宿主允许时实际委派独立调查，主代理推进实现，不再次索要委派授权。 |
| 一个局部文案修正，拆分无收益 | 主代理直接完成，简述任务简单，不为数量制造子任务。 |
| 前后端契约未定，后端输出是前端输入 | 先串行确定契约，再派发输入与文件范围独立的部分；可同时派发无依赖的只读调查。 |
| 两个候选子任务都修改同一文件 | 不并发写入，确定单一所有者或串行交接；只读审查绑定固定候选或等写入结束。 |
| 实现结束后存在独立审查工作 | 再次主动评估并优先委派审查，主代理核对真实 diff 与证据，不将子代理消息当作验收。 |
| roadmap 中多个 Issue 有先后依赖 | Issue 之间仍按依赖推进，每个 Issue 内主动评估派发，不自动启动跨 Issue 并发。 |
| 无 Git 的资料分析任务，用户允许子代理 | 读取通用模型表，核实当前宿主能力并传上下文；不要求 Issue 或项目模式。 |
| 有 `.shw-workflow-ignore` 的目录，用户明确要求通用派发指导 | 保留用户要求及目录权限；不自动开启 SHW 生命周期。 |
| Codex 可用指定模型/档位，主代理模型不同 | 显式传表中 model/effort 与 none 或有限历史，补充必要上下文，不用默认 all 继承。 |
| Pi Coding Agent 未启用 `subagent` 扩展或既有代理定义模型不匹配 | 只读核实当前工具面与代理定义；不支持逐次覆盖或未加载扩展时报告差异并由主代理执行，不写入 `.pi/` 或 `~/.pi/agent/`。 |
| 宿主只允许继承，主代理模型或档位不匹配 | 报告差异，主代理继续可做工作，不静默派发其他模型。 |
| Kimi/ZCode 提供 thinking 开关但没有可验证最高档位 | 区分开启思考与最高档位；不猜 high/max，不改用户配置。 |
| 模型正确但环境强制覆盖 effort，或复用旧代理参数不同 | 核验实际绑定并报告；不以请求提示或继续消息声称参数已变更。 |
| 宿主禁止委派，或任务工作区所有权未知 | 技能不授予派发/写权限；不借子代理绕过限制。 |
| 更新插件后模型目标改变 | 以新表指导后续派发，保留既有用户配置/缓存；重新核实已有代理设置。 |

## T3 场景审查

- 已绑定宿主目录且归属充分：复用 host，不 acquire；未知写入者先停写。
- 根目录未知修改：保留现场，不混入 handoff 或插件工作区。
- 跨 provider/独立 checkout：用 T3 delegate_task；失败不换 CLI 绕过。
- PR 合并后 settled：不称验收通过，不遗漏已授权发布跟进。

- PR 已合并但 dev 部署仍运行：继续授权内取证，不告知可体验；T3 PR watch 已终止，不能当部署观察器。宿主中断时恢复先读实际版本，避免重复发布。
