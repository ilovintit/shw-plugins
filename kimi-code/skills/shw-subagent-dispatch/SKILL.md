# 通用子代理派发

每次创建子代理、让已有子代理继续新工作或审查派发设置时，读取 [模型与宿主能力](references/models.md) 的当前宿主条目；同一会话可复用当前已加载的版本，插件版本改变时重新读取。它是唯一模型偏好来源，随插件版本更新；不要在项目或用户配置里复制模型表。

本指导不以 Git、Issue、`.shw/project.yaml` 或 SHW 工作流为前置。`.shw-workflow-ignore` 只影响 SHW 生命周期接入，不取消用户明确要求的通用派发指导，也不授予派发或写入权限。技能自动发现是提示指导，不能承诺宿主在每次工具调用前加载它或硬拦截错误参数。

## 派发决策

先确认当前用户/宿主允许委派；本技能的加载和模型偏好本身不构成授权。对简单任务直接完成；可独立的子任务才派发。遵循当前工具 schema、模型可用列表和实际思考档位；不把产品名称当作已验证模型 ID，不把“最高”猜成 `max` 或 `high`，不把请求文字当作运行参数已生效。

能逐次指定时显式传模型与档位；仅能继承时核实继承结果是否满足表中要求。缺参数、模型不可用、被宿主强制覆盖或实际运行值不符时，报告具体能力差异，不静默换模型、降档或伪称已满足。主代理继续能够完成的原任务工作；原任务授权不需要因此再次批准。需要用户选择替代模型或更改配置时才呈现具体差异与选择，不擅改用户文件、环境、插件缓存或凭据。

## 上下文、工作区与回收

派发携带目标与验收、必要材料/路径、已确认决策、约束与授权、真实工作目录、可写文件范围和禁止项、期望证据。写入任务明确所有权与互斥；非 Git 任务同样不得接管未知文件或资源，项目外只读边界不随委派改变。仅 SHW Issue 工作额外读取 `shw-issue-parallel` 的 Issue/工作区约束，通用任务不因此进入完整生命周期。

已有代理继续工作前核对实际模型/档位与原上下文、目录、权限是否仍适用；无法在原代理修改设置时，不把 follow-up 当作已经重新绑定模型。核对已有任务避免重复派工，关联依赖串行推进。收回结果后审查实际产物与验证证据；不将子代理完成消息代替验收、CI、发布授权或宿主运行证据。

维护时用 [行为场景](references/scenarios.md) 核对边界；结构与分发验证不能代替宿主实机验收。
