执行前必须读取 `shw-issue-gate`；修改前读取 `shw-workspace` 并确认项目、目录、Issue 与所有权。项目外只读，未知修改不覆盖；能力缺失不扩大授权。

# 体验与验收

体验前必须通过类型检查、适用静态检查和受影响模块单元/API 快速测试，并完成必要构建与部署。部署后只读取 Fleet/工作负载/制品状态并提供入口；人工实际体验与自动测试分开记录，长周期全量回归集中在 dev→main 集成。

每项体验记录：Issue/AC、源码 commit、制品 digest、部署 revision、环境与入口、角色及受控数据、步骤、用户反馈原文/可访问引用、验收范围及时间。不得泄露凭据或业务明细。

状态明确区分：实现完成、部署可访问待体验、已人工验收、需要修正、未验收。CI 绿、Pod Running、截图存在、用户“继续”都不自动构成验收。连续开发授权仅允许推进，仍记录未体验范围。

业务/权限/状态变化同步 PRD；API/数据/架构变化同步技术文档，与代码同一变更交付。新的行为改变使受影响验收失效，重新体验和确认后才能回到集成。无独立原型或产品终审阶段。

集成前按 `shw-integration` 将已验收 Issue/commit/制品范围锁定；不把旧候选反馈套在新 SHA。生产发布后的观察与用户反馈继续留证，不在 tag 阶段另跑自动测试。
