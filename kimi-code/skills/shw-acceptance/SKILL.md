# 体验与验收

完成必要构建与已授权部署后提供入口，用户可在生产环境实际体验。发布前人工验收和自动测试均非默认前置；测试只在明确请求后于test分支执行，不自动运行冒烟。读取Fleet/工作负载/制品状态与业务测试分别记录。

每项体验记录：Issue/AC、源码 commit、制品 digest、部署 revision、环境与入口、角色及受控数据、步骤、用户反馈原文/可访问引用、验收范围及时间。不得泄露凭据或业务明细。

状态明确区分：实现完成、部署可访问待体验、已人工验收、需要修正、未验收。CI 绿、Pod Running、截图存在、用户“继续”都不自动构成验收。连续开发授权仅允许推进，仍记录未体验范围。

业务/权限/状态变化同步 PRD；API/数据/架构变化同步技术文档，与代码同一变更交付。新的行为改变使受影响验收失效，记录受影响范围，按授权继续集成/发布，实际体验由用户安排。无独立原型或产品终审阶段。

集成按 `shw-integration` 锁定已授权的 Issue/commit/制品范围，人工验收事实可选附加；不把旧候选反馈套在新 SHA。生产发布后的观察与用户反馈继续留证，不在 tag 阶段另跑自动测试。
