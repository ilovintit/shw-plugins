# 架构设计审查

逐项检查：

1. 每项架构能力能回指 PRD目标或非功能要求，不暗中扩需求。
2. 每个入口的 HTML原型及可选实现映射中的字段、动作、状态、权限、响应式和可访问性都有明确数据、接口或客户端实现支撑；派生映射不得暗改业务语义或与原型竞争视觉真相。
3. 跨入口旅程在服务、事件、权限和一致性模型中闭环。
4. 数据模型含约束、唯一性、生命周期、迁移和审计；API含鉴权、幂等、错误、分页、并发和兼容。
5. 失败模式覆盖外部依赖、超时、重试、部分成功、回滚和可观测性。
6. 测试策略能映射产品验收；部署方案覆盖镜像、配置、迁移、Fleet、健康和回滚。
7. 项目 Agent 不使用 Ansible、不持有 kubeconfig/Token、不直接写 K8s；集群查询只经只读 MCP。

输出阻断、需用户裁决、可改进三类。确定性问题直接修正；产品范围、公开契约和重要权衡必须由用户裁决并写回权威文档。
