# Issue 入口闸门

## 文件系统边界（所有命令与 Skill 通用）

- **项目外只读，一字符也不得修改**：写入范围仅为已确认的当前项目工作目录；进入 Issue worktree 后，以返回的该工作区为文件编辑边界，主 checkout、其他 Issue 工作区及相邻仓库不因属于同一项目而自动可写。新项目初始化仅允许已确认的目标目录。
- 外部路径禁止创建、修改、删除、移动、重命名、权限变更或任何内容写入；包括用户级配置、shell profile、插件安装/缓存文件、共享库源码、跨项目端口登记表。可按任务需要读取，读取不代表写权限。
- 按真实路径判断归属；符号链接、相对路径、切换 cwd、脚本、子进程、MCP 或委派都不能绕过边界。已知会改写外部文件的安装、构建、修复命令也不得直接执行；可将缓存、临时输出定向到当前工作区内，否则交用户处理。
- 需要外部修改时，**先停止相关写操作**，报告目标绝对路径、必要原因、拟修改内容和受阻步骤；请用户介入，由用户安排其他获授权 Agent 或手动处理。本 Agent 可提供补丁/操作说明，但不得自行跨目录执行，也不得自行委派外部写入；处理后只读复核，再继续项目工作。“全部完成”“自动修复”“继续”不等于外部目录写授权。
- **有限运行例外**：正常调用插件 Worktree MCP 创建/管理本项目受管工作区及维护其状态、在当前工作区执行已授权 Git 操作所必需的仓库元数据写入，以及 Gitea shim 正常维护自身后端缓存，属于程序既定运行行为。例外只覆盖这些程序操作，不允许 Agent 手改状态、缓存、用户配置、其他工作区或借此修复外部环境。
- Gitea Issue/PR/Milestone 等远端操作继续遵循对应用户授权与生命周期规则；本条本地目录边界不新增远端操作权限。本文为提示词纪律，不增加沙箱或运行时拦截。

## 判定

- 纯读调查、答疑、状态查询：不建单。
- 会改仓库文件、文档、CI或仓库配置：必须先有匹配的 Issue；文件修改进入其独立工作区。
- 已授权的生命周期元数据操作（创建/更新 Milestone、拆分 Issue、测试映射、发布状态、关闭记录）直接使用该 Milestone/Issue/PR 为载体，不额外创建状态 Issue、空分支或空 worktree。
- 外部操作权限仍以用户授权与宿主规则为准。纯元数据豁免不能用于绕过代码/配置变更闸门。
- `/shw-init` 在新仓库设施尚不存在时允许先建立初始化载体；一旦 Gitea 可用立即关联。

## 执行

先按上节分类：仅操作已授权生命周期元数据时，核对载体后直接执行并回读验证，到此返回。以下 1–5 步仅适用于需要 Issue 的仓库内容/配置变更。

1. 用户给了 Issue：读取并确认与任务匹配。
2. 未给：按关键词搜索 open Issue，避免重复。
3. 仍无：优先经 Gitea MCP；不可用时读取 `config.md` 的 REST 兜底指引。创建标题清晰的 Issue，写背景、目标、约束和初步验收；产品需求应先进入产品定义，缺陷用 `/shw-bug`。
4. 涉及文件修改时加载 `shw-worktree`，确认当前目录与编号分支属于该 Issue。仅操作已授权元数据时不执行建工作区步骤。
5. 再开始修改。

产品文档的一次一致性变更使用一个产品定义 Issue；Version 的多个交付 Issue 由 `/shw-split` 创建。不得为了每个内部动作或文档类型重复建单。

用户明确要求不建 Issue 时记录豁免；除此之外，无单开工和事后补单都不允许。
