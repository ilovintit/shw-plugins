细化审查未发版 PRD 的完备性：多视角无锚定审查逼出 PRD 该记而未记的内容，问题清单经用户裁决后一条龙写回 PRD 并留痕，最后给出就绪度软结论。审的是**契约 vs 需求空间**——业务逻辑、操作习惯、领域事实、数据库结构有没有漏。

与 /shw-prd-audit 的边界：audit 审**契约 vs 实现**（完成度对账），发生在实现后的任何时候；本命令发生在 **roadmap 拆分前的细化循环相位**。与 /shw-prd-revise 的边界：入口上"主动变更走 revise、审查驱动变更走 review"，本命令内嵌 revise 同款审核门与留痕纪律，**不转交命令**（slash 命令间不能可靠互调）。可**多轮重跑**（含新会话）：跨轮收敛靠 PRD 变更记录内的留痕传递状态——PRD 是单一真相源，不靠外部报告。

---

**输入**：`/shw-prd-review` 后的参数是版本号（如 `v2.3`；未带 v 前缀时先归一化为带 v 形态再匹配）。PRD 存放 `docs/prd/vX.Y-主题slug.md`，版本粒度一版本一文件；落盘即定稿，细化审查只针对未发版（契约态）PRD。

**步骤**

1. **定位 PRD 文件**

   - **参数未提供**：列出 `docs/prd/` 下的 PRD 文件（目录不存在则提示尚无任何 PRD、起草走 /shw-prd-draft）让用户指定一个，不猜默认版本。
   - **参数有版本号**：用 glob 定位（版本号后紧跟 `-`，所以 `v2.3-*` 不会误匹配 `v2.30-x.md`）：

     ```bash
     ls docs/prd/<版本号>-*.md
     ```

     - 恰一个 → 用之，继续下一步
     - 零个 → 向用户提示该版本 PRD 不存在、起草走 /shw-prd-draft，停止
     - 多个 → 列出全部让用户指定，**不猜**

2. **发版标记检测**

   ```bash
   grep -m1 '^> 已发版：' docs/prd/<文件>
   ```

   - 有输出 = 已发版冻结 → 劝阻并停止，向用户提示："该 PRD 已发版冻结，细化应针对新开 PRD，新需求走 /shw-prd-draft 起草下一版本"（冻结契约无细化义）
   - 无输出 = 契约态，继续

   发版标记是墓碑单向的：本命令不提供任何移除/修改发版标记的路径。

3. **多视角无锚定审查**

   **并行委派多个独立审查视角**：每个视角由一个**不携带本对话上下文的独立审查代理**承担（所用工具的委派机制自行映射，子代理天然不继承对话历史即满足无锚定要求）；所用工具不支持委派时，退化为串行自查各维度，并**向用户声明该局限**。每个视角只拿 PRD 全文与本维度审查指令，不拿本对话历史。

   视角维度（至少五个）：

   | 视角 | 审什么 |
   | --- | --- |
   | 业务逻辑完备 | 主流程 / 异常流 / 边界条件 / 业务规则（计算、校验、状态联动） |
   | 用户操作流 | 角色 / 入口 / 步骤 / 状态反馈 / 误操作与恢复路径 |
   | 数据库结构 | 每张表字段类型约束索引是否齐全；有需求没落表、有表没需求来源；表间关系是否覆盖业务规则 |
   | 三方一致性 | 需求 ↔ 数据库设计 ↔ WebUI 流程互相咬合（同一状态机在表字段与界面流转上是同一套） |
   | 离场可执行性 | 总判据：把任一需求交给无上下文 agent，从 roadmap 拆分到 change design 实现全程无需问人；任何必须问人的点即洞 |

   各视角的**审查实证姿势**（找洞方法）：

   - **数值参数**逐个问默认值与可配置性——可配置项进横切资产·全局配置项清单
   - **每个实体**问状态机——状态定义进横切资产·状态枚举
   - **横切关注点**（通知 / 权限 / 配置）强制矩阵化——进横切资产对应矩阵
   - **每个流程**问超时 / 失败 / 降级三分支——缺哪个分支即洞
   - **"明确不处理"也是裁决**：审出的异常路径经用户裁决不处理的，必须写进非目标节

   视角纪律：各视角开审前先读变更记录节，**读到否决留痕的问题不再重提**。每条发现含：问题描述 / 判定依据 / 建议落点（应补进哪个要素节）。

4. **问题清单展示与用户裁决**

   汇总各视角产出，去重合并后按三级分级，**只在对话展示，不落盘任何独立报告文件**：

   - **P0**：拆分执行必然阻塞——agent 必须瞎猜才能继续的点
   - **P1**：高概率分叉——存在两种以上合理理解、会导出不同实现的点
   - **P2**：建议——不影响可执行性的改进建议

   请用户逐条裁决：**采纳**（进写回）或**不采纳**（进否决留痕）；可分批裁决，裁决完成后进下一步。

5. **一条龙写回（内嵌 revise 同款纪律，不转交命令）**

   - **采纳的问题**：起草变更摘要——改哪些要素节 / 为什么 / 影响哪些需求与验收标准，向用户展示；**审核门是硬门**，用户确认前 PRD 文件保持原样；确认后修改 PRD 对应节，并在变更记录节追加留痕：

     ````markdown
     ### YYYY-MM-DD <一句话摘要>

     - 改动：<补齐了哪些要素节/需求>
     - 经用户确认
     ````

     新写入的验收标准同样执行可取证纪律：能跑命令比对 / 发请求看响应 / 指到界面检查点。

   - **不采纳的问题**：在变更记录节否决留痕，格式：

     ````markdown
     ### YYYY-MM-DD 审查否决：<一句话问题>

     - 提出：<问题描述与来源视角>
     - 不采纳理由：<为什么不做>
     - 经用户确认
     ````

   完成后向用户输出：改了哪些节、留痕条目落在何处。否决留痕是跨轮收敛的载体——后续轮次（含新会话重跑）读到即不再重提同一问题。

6. **就绪度结论**

   写回完成后给出就绪度结论，三档：

   - **可离场执行**：P0 清零、P1 已消解或已有明确裁决、空节占位清零
   - **建议先补 X**：X 为未消解的关键问题（指向具体要素节）
   - **不可拆分**：P0 大面积存在或要素节大面积空缺，先补 PRD 再谈拆分

   给出"可离场执行"前**必须**确认 draft 留下的空节占位注释已全部清除（占位未清零即要素未补齐）：

   ```bash
   grep -n '<!-- 待 /shw-prd-review 补齐' docs/prd/<文件>
   ```

   有输出 = 占位未清零，不得给"可离场执行"。

   就绪度结论是**纯软建议**：不做成 roadmap-explore 或任何下游命令的硬门，拆不拆由用户决定。

**约束**

- **问题清单只在对话展示**：不落盘任何独立报告文件；唯一的写动作是写回 PRD 本身（修改 + 留痕）
- **已发版必劝阻**：检测到发版标记一律劝阻并停止，提示细化针对新开 PRD；不提供移除/修改发版标记的路径
- **多文件匹配必让用户选**：glob 命中多个文件时列出全部让用户指定，不猜
- **否决留痕不重提**：审查视角读到变更记录中的否决条目即不再把该问题作为发现提出（新会话重跑同样生效）
- **用户未确认不改文档**：审核门是硬门，变更摘要未获用户确认前 PRD 文件保持原样
- **就绪度纯软建议**：结论只是建议，任何下游命令不强制检查，拆不拆由用户决定
- **除写回 PRD 外零写副作用**：不写任何其他文件，git 查询只读
