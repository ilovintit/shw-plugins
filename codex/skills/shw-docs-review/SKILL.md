# 产品文档审查

## 双向检查

- 用户裁决和 Issue → PRD/原型/架构：不得遗漏、弱化或改变。
- 文档 → 用户裁决和证据：不得添加无来源的产品范围。
- 原型执行与文件组织：当前Agent直接维护、公司前端规范优先、PRD免重复问询、稳定角色端入口、语义页面及完整相对依赖；模拟接口/组件与真实验收分清，不依赖外部任务或另一套存储。
- PRD ↔ 原型：角色、字段、动作、状态、异常、视觉、响应式、可访问性和跨端旅程闭环；原型由当前Agent按公司规范在docs/design直接维护并带有完整可运行依赖。
- 原型 ↔ 可选实现映射：`ui-design.md` 只能同步解释当前原型的 token、组件、响应式和可访问性，不能暗改业务规则、保留未同步的竞争性差异或成为第二份视觉真相；存在时由入口索引链接。
- PRD/原型 ↔ 架构：数据、接口、权限、测试和部署可实现。
- 文档 ↔ 代码：`/update` 场景下以真实实现和迁移为证据标记漂移，但产品意图冲突仍交用户裁决。

检查链接、索引、术语、单一权威定义和所有拆分文件，不能只审 index。结果分阻断、需裁决、改进；确定性问题在同一分支直接修正后复审。没有新鲜 diff与完整文档读取，不得放行 docs PR。
