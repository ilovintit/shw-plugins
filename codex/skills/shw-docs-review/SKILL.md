# 产品文档审查

## 双向检查

- 用户裁决和 Issue → PRD/原型/架构：不得遗漏、弱化或改变。
- 文档 → 用户裁决和证据：不得添加无来源的产品范围。
- PRD ↔ 原型：角色、字段、动作、状态、异常和跨端旅程闭环。
- PRD/原型 ↔ 架构：数据、接口、权限、测试和部署可实现。
- 文档 ↔ 代码：`/update` 场景下以真实实现和迁移为证据标记漂移，但产品意图冲突仍交用户裁决。

检查链接、索引、术语、单一权威定义和所有拆分文件，不能只审 index。结果分阻断、需裁决、改进；确定性问题在同一分支直接修正后复审。没有新鲜 diff与完整文档读取，不得放行 docs PR。
