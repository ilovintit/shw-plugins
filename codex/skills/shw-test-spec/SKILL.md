**项目外只读**：仅修改当前Issue工作区。缓存服务、镜像仓库和Action镜像的维护按已有授权与基础设施职责处理，不编辑其他仓库或用户配置，不使用项目Agent执行Ansible/Kubernetes写操作。

# 统一测试规范

## 选择范围与分支门禁

- 所有测试类型都必须能按模块或文件执行，测试入口默认不全跑。无选择器时给出用法并退出，不能把空选择、无匹配、选择失败当成全量或成功。
- Issue分支→dev：快速门禁，只执行构建/静态检查及与该Issue实际改动相关的小范围单测/模块测试，禁止全测。用变更文件、受影响依赖与AC建立明确映射，记录所选模块/文件及原因；共享代码变化要列明影响范围，跨模块时细化到相关用例/文件，不能用“保险起见”全测兜底。
- 只有同仓库dev→main发布PR可以并且必须执行全量测试门禁。即使tree相同、Issue测试已绿，也不能复用定向测试或历史全量结果跳过本次门禁。
- Hotfix→main、main→dev同步及手动定向运行仍按实际改动选模块/文件，不借分支名或手动开关取得全测权限。纯历史同步没有内容差异时记录无适用测试；未知路径/失效映射必须修正，不静默跳过或扩大到全量。
- 测试目录按业务模块组织，公共fixture/helper与用例分离；测试之间不依赖运行顺序，不要求先跑全套才能执行一个文件。框架原生筛选参数由项目统一入口转发，不能在脚本内悄悄丢弃选择器。

## 三类测试边界

- **API**：按AC验证接口协议、校验、鉴权/越权、状态变化和必要副作用，不只检查HTTP 200。数据与依赖由用例准备并清理；真实服务和stub的边界在test-plan写明，不把mock结果说成真实集成。
- **E2E**：按业务模块覆盖用户关键旅程与跨端协作，测试真实可操作界面及其约定依赖；不机械重复所有API断言。明确环境、账号角色、起止状态和重置方式；缺环境或认证前置时报错说明，不能用skip伪造通过。
- **VRT**：按页面/组件/模块与视口选择，对已认可的基线比较。浏览器、字体、时区、数据、时间和动画等影响因素固定或记录；用明确就绪条件截图，不用无限等待。基线来源、初次生成、审阅/更新权限和阈值由项目test-plan明确；缺基线不算通过，未经批准不得自动重录、放宽阈值或掩盖真实差异。

三类测试的样例、目录映射与执行方式见 [选择与证据](references/execution.md)。测试覆盖率和像素阈值不在此设武断全局数值，按已确认验收目标选择。

## 执行位置与证据

默认只能在Gitea CI运行。开发中确有必要快速验证时，只经项目AGENTS/运行说明指定的入口执行明确的小范围单测，记录必要性、命令与结果；不能自行绕过项目运行路由或跑本地全套。该例外不替代合并所需CI。

TDD继续由shw-tdd管理，但红绿都按Issue相关范围运行。当前HEAD的定向CI只证明所选范围；发布全量CI才证明发布测试矩阵。API报告、E2E trace/日志和VRT expected/actual/diff应可定位到具体模块/文件及失败用例。内容审查、人工验收、自动化证据分开，不恢复机械文案关键词断言。

## 内网依赖优先且无静默公网回退

所有CI Docker镜像统一存于公司Harbor的 `ci-cache` 项目；GitHub Actions使用同步到Gitea `actions` 组织的镜像；npm与Go依赖走公司缓存/加速源。具体预热、认证和版本固定要求见 [CI依赖缓存](references/ci-cache.md)。源缺失时先按已有授权从上游补齐缓存，权限不足才交维护者处理，不能因为CI有国际出口就大量回源下载。

## 合并后开发部署

快速门禁不包含共享开发环境部署或全量 API/E2E/VRT。合入 dev 后按 [环境契约](../shw-release-flow/references/environments.md) 自动更新变化的 API/Web；部署就绪/冒烟不替代发布全量测试，小程序由用户本地连接开发 API 调试。公共变量和密钥使用 [统一名称](references/ci-config.md)，同用途同名、凭据按权限隔离。
