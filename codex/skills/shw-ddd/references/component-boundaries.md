# 组件库组件归层约定

项目引入组件库（如会话、短信、加密、序列号、分布式锁、存储等）时，组件按性质归层。这是跨语言的通用约定：

| 组件类型 | 归层 | 理由 |
|---------|------|------|
| 会话/认证服务（session） | infrastructure | 技术基础设施，与业务无关 |
| 认证/权限中间件 | infrastructure | 横切关注点的技术实现 |
| 短信/企微/通知通道 | infrastructure | 外部通道，技术实现 |
| 加密/序列号/分布式锁 | infrastructure | 技术工具服务 |
| 存储驱动/地区数据源 | infrastructure | 基础设施适配 |
| 请求/响应 DTO | application | 应用层数据契约 |
| 仓储接口 | domain | 数据访问契约属于领域 |
| 业务枚举/业务错误码 | domain | 承载业务语义 |
| 全局错误码/通用状态码 | shared | 跨模块共享 |

**中间件归层的边界**：中间件的**代码实现**归 infrastructure（它是认证机制的技术实现）；interfaces 层负责把它**装配**到请求管道。interfaces 不含技术实现细节，只负责组装。

**组件库与业务解耦**：组件库本身是独立的项目，不依赖任何业务模块。业务项目在 infrastructure 层接入组件库（实例化、配置、包装成领域需要的接口），domain 层只依赖自己定义的抽象接口，不直接依赖组件库。
