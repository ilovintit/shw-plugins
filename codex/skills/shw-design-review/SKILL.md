# 设计审查

围绕当前可体验切片，检查模块依赖、接口/数据所有权、权限边界、状态转换、并发/失败恢复、兼容与部署成本。用实际代码和已确认需求支撑判断；不为未知将来需求搭建框架。

方案只需够用，直接落地真实前端和后端。交互反馈来自实际版本，无独立原型阶段。影响公开契约或产品范围的分歧提出具体选择，由已有授权或用户裁决。

结论随本次 PR 记录；技术变更同步技术文档，业务变更同步 PRD。审查不代表测试或人工验收已完成。

新产品没有既有 schema 时，从用户需求、当前 PRD 和已确认业务概念推进数据模型与迁移方案；不虚构“必须先提供数据库”的前置条件。只有真实业务歧义集中请用户裁决；需要验证生成时按一次性数据库规则处理，设计授权不等于共享库迁移授权。
