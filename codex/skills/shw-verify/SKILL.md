# 完成前验证

## 概述

声称工作完成而没验证是不诚实，不是高效。

**核心原则**：声称之前先有证据，永远如此。

**违反规则的字面意义就是违反规则的精神。**

## 铁律

```
没有新鲜的验证证据，不声称完成
```

若你这次响应没运行过验证命令，你不能声称它通过。

## 门禁函数

```
声称任何状态或表达满意之前：

1. 识别：什么命令能证明这个声称？
2. 运行：执行完整命令（新鲜的、完整的）
3. 阅读：完整输出，检查退出码，数失败
4. 验证：输出是否支持声称？
   - 否：附带证据陈述实际状态
   - 是：附带证据陈述声称
5. 仅在此时：做出声称

证明级别匹配声称级别：
- 编译级声称（build/typecheck）用本地命令输出证明
- 合并所需证据按shw-test-spec区分：Issue→dev必须是当前HEAD相关模块/文件的CI结果；dev→main必须是当前发布候选实际执行的全量CI，仅按shw-test-spec/references/history-sync.md允许同一发布PR的main回灌纯历史同步复用；不复用其他旧全量或定向结果跳过。开发中必要本地单测须走项目指定入口、记录小范围与结果，不能替代CI。失败由work/roadmap读取日志并处理到关联检查通过；外部阻塞或产品裁决才交用户。

跳过任何步骤 = 在撒谎，不是在验证
```

## 常见失败

| 声称 | 需要 | 不够 |
|-------|----------|----------------|
| 合并所需测试通过 | 当前 HEAD 的 PR CI run 链接 + required job 绿 | 本地结果、之前跑过、"应该通过" |
| Linter 干净 | Linter 输出：0 错误 | 部分检查、推测 |
| 构建成功 | 构建命令：exit 0 | Linter 通过、日志看起来好 |
| Bug 已修 | 测原始症状：通过 | 代码改了、假设修好了 |
| 回归测试有效 | 验证红绿循环 | 测试通过一次 |
| 子智能体完成 | VCS diff 显示改动 | 子智能体报告"成功" |
| 需求满足 | 逐项清单 | 测试通过 |

## 红旗 - 停下

- 用"应该"、"大概"、"似乎"
- 验证前表达满意（"好了！"、"完美！"、"搞定！"等）
- 准备 commit/push/PR 但没验证
- 信任子智能体的成功报告
- 依赖部分验证
- 想"就这次"
- 累了想收工
- **任何措辞暗示成功但没跑验证**

## 防止合理化

| 借口 | 现实 |
|--------|---------|
| "现在应该可以了" | 运行验证 |
| "我有信心" | 信心 ≠ 证据 |
| "就这次" | 无例外 |
| "Linter 通过了" | Linter ≠ 编译器 |
| "子智能体说成功" | 独立验证 |
| "我累了" | 疲劳 ≠ 借口 |
| "部分检查够了" | 部分证明不了什么 |
| "措辞不同所以规则不适用" | 精神高于字面 |

## 关键模式

**测试（一切层级）：**
```
✅ 提交推送 → PR CI run 链接 + 对应 job 绿 "所有测试通过（CI run：<链接>）"
❌ 用本地结果替代 required CI / "现在应该通过"/"看起来对"
```

**回归测试（TDD 红绿，判定在 CI）：**
```
✅ 写复现测试 → 推送（CI 红）→ 修复 → 再推（CI 绿）——红绿两截 CI 记录可查
❌ "我写了回归测试"（无 CI 红绿记录）
```

**构建：**
```
✅ [运行构建] [看到：exit 0] "构建通过"
❌ "Linter 通过"（linter 不检查编译）
```

**需求：**
```
✅ 重读计划 → 建清单 → 逐项验证 → 报告缺口或完成
❌ "测试通过，阶段完成"
```

**子智能体委派：**
```
✅ 子智能体报告成功 → 检查 VCS diff → 验证改动 → 报告实际状态
❌ 信任子智能体报告
```

## 为什么重要

来自真实失败案例：
- 用户说"我不信你"——信任破裂
- 未定义函数被发布——会崩
- 漏掉的需求被发布——功能不完整
- 假完成上浪费的时间 → 返工 → 重做
- 诚实是核心价值。虚假声称摧毁信任。

## 何时应用

**总是在以下之前：**
- 任何变体的成功/完成声称
- 任何满意表达
- 任何关于工作状态的正面陈述
- commit、创建 PR、标记任务完成
- 进入下一任务
- 委派给子智能体

**规则适用于：**
- 精确短语
- 转述和同义词
- 暗示成功
- 任何暗示完成/正确的沟通

## 底线

**验证没有捷径。**

运行命令。读输出。然后声称结果。

这是不可协商的。
