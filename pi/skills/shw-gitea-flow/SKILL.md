# 仓库与分支路由

先读取 `.shw/project.yaml`、当前 Git remote 和项目规则，不从目录名猜宿主或权限。Gitea 优先适配的 MCP；GitHub 使用其已授权连接。不可用时按 `shw-issue-gate/config.md` 的适用兜底；不读凭据文件或新设权限。

| 模式/动作 | source → target | 收口 |
| --- | --- | --- |
| issue-main 普通 Issue | main → main | 项目明确授权的 PR 合并；不擅自引入 dev 或业务测试门禁 |
| issue-dev / managed 普通 Issue | dev → dev | 自审、必要构建与部署证据；无自动测试前置 |
| issue-dev / managed 集成 | 冻结 dev 与 main 基点 → main | Agent 准备并核对集成 PR，交用户手动 merge，回读实际结果 |
| Hotfix | main → 项目明确的修复目标 | 不自动直合 main；需指定集成/发布及回灌策略，保持授权、来源与正常合并约束，不要求测试/冒烟前置 |
| 发布 | 已通过集成的 main commit/制品 | tag 或审批按 `shw-release-flow`，不再运行测试 |

表中 source 是创建分支的来源，不是允许在保护分支直接编辑。`issue-main` 无 dev→main 阶段；普通PR不自动测试；test仅承载用户明确要求的独立测试，不是main发布前置或自动合入来源。

所有 PR 检查必须对应当前 HEAD。Issue关联、合并、关闭、分支删除等远端写入按用户/项目授权执行，并回读验证。无权限则保留具体待办；不 force、绕保护、伪造 checks 或删除他人分支。不将普通“完成”理解为发布授权。

## 合并责任与拒绝处理

每次合并决策和合并被拒绝时必须读取 [合并执行人与推进规则](references/merge-authority.md)。dev→main 默认由用户手动合并，发布/继续请求与 CI 通过不覆盖人工约定；Agent 准备 PR、完成必要检查后交接，实际 merged 后再继续已授权发布。冻结 dev 的集成分支同样受此约束，不按 head 名称绕路由。

合并被拒绝分两类：dev→main 回读后反馈 PR 与检查状态，请用户手动合并；其他已授权由 Agent 合并的 PR 继续查当前 HEAD 的门禁，运行中就等待，失败就诊断修复，通过后重试正常合并。不能以拒绝本身停工；仅确切权限、审批或无法在授权内处理的阻塞需用户介入。HTTP 状态码不单独证明原因，只读诊断不授权换工具/身份绕过限制。

## 交付 Issue 关闭

普通交付 PR 实际合入本模式目标分支后，立即关闭对应已完成范围的 Issue：`issue-dev` / `managed` 合入 `dev` 即关闭，`issue-main` 合入 `main` 即关闭。关闭是已授权交付的收尾动作，不要求用户再确认人工验收。`closed` 表示本工单开发交付完成，可同时记录未部署、待体验、未验收或未测试；不等待 dev→main、tag、正式发布或后续反馈。关闭工单不取消已授权的 CI、构建或部署跟进，失败仍须处理并如实记录。

1. 回读 PR 的实际 merged 状态、base、merge commit 与关联 Issue，核对本次交付范围；只有 closed 但未 merged、仅已推送、CI 绿或部署成功均不能当作合并证据。
2. 覆盖完整交付范围的 PR 可写 `Closes #N`，但不假设合入非默认分支也会自动关单。回读 Issue，仍 open 时显式更新为 closed，再回读验证；确认范围已完成且已自动关闭则无需重复关闭。记录 PR 链接、目标分支、merge commit 和独立的体验/测试状态。
3. PR 仅完成部分已约定范围时，只关联总单，不对它使用关闭关键字；可关闭本次完成的子单，或明确拆分剩余工作后收口。若自动误关了仍有未拆分开发待办的总单，按授权重开并回读，保留真实剩余工作。待验收、待发布和等待可能反馈不属于未完成开发范围，不能用它们保留工单打开。
4. 后续验收发现问题，优先新建关联修正 Issue；也可按实际反馈重新打开原 Issue，记录问题与新的修正范围，使用新 PR，合入后再次关闭。没有新问题时不预先重开，不把单纯“继续”当作缺陷反馈。
5. 发现已合并但因等待验收遗留的 open Issue，在当前授权项目/工单范围内核对上述证据后补关。不能据此批量修改未授权项目。工具拒绝或结果未知时回读状态，报告真实失败或待确认项，不伪报已关闭、不绕权限。

每日/小批次合入 main 是集成，不触发本插件默认生产发布。项目现有 main push 自动部署必须单独审计、明确迁移授权；文档更新不代表业务 CI/Fleet 已改。
