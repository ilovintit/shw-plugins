# 工作区能力契约

先读取 `shw-issue-gate`。纯读调查与已授权元数据操作不创建工作区。文件变更必须先确定 repo、Issue/本地授权任务、来源分支、实际目录和所有者，检查已有任务、分支、PR及工作区，避免重复派工。

## 选择提供者

1. 已有属于当前任务的隔离工作区：核对宿主/提供者返回的真实路径、分支、来源和所有权，再复用。用户明确选择的工作区不自动迁移或删除。
2. 宿主提供隔离能力时优先选择宿主；已安装 shw-worktree 不改变当前目录的提供者。T3 Code 按下节核对，其他桌面端按其实际目录、任务归属和活动写入者证据核对。云端同样无需本地插件。
3. 需要独立本地隔离且未选择宿主提供者时，若 shw-worktree 可用，加载其技能并使用 worktree 工具 acquire/inspect/list/release/remove/reconcile。主 SHW 不注册这些工具、不手改状态或用户配置。
4. 本地缺少插件或既有提供者不可用：只读检查现有工作区；不能把工具不可用解释成无占用，不能自动新建同 Issue 分支、复制目录、借他人 claim 或绕过失联提供者。已有明确授权、宿主独占的隔离工作区可继续；否则停止依赖写入并报告缺失证据，不自动安装插件或改用户配置。

## T3 Code 宿主工作区

按当前 schema 发现 T3 的 worktree status/list 与线程读取工具；环境变量、路径形状或工具名称本身都不证明所有权。status 返回 attached/path/branch 后，与真实 cwd、Git common-dir、分支、来源基点和当前任务核对；再检查已有线程、工作区、分支/PR与活动写入者。status/list 不是跨宿主锁，不能仅凭 attached=true 宣称独占；未知写入者或未解决的其他 provider 占用先停止相关写入。

- 已绑定当前任务的 T3 worktree：使用通用 provider=host，保留线程/目录/分支与证据来源；不调用 worktree.acquire、不另建目录或登记插件 claim。线程标识只作关联证据，不伪造认证。
- attached=false：纯读继续；需要 Issue 文件变更时先核对根目录未知修改和任务占用，再通过 T3 worktree handoff 进入正确来源分支的新编号分支。按工具规定最后调用并附继续提示；无法安全迁移时停止依赖写入，不能用 shell 创建旁路 worktree。
- 已由独立插件管理的目录继续沿用原提供者；不因进入 T3 自动搬迁、抢占或清空状态。
- T3 worktree 由 T3 管理和清理；不调用独立插件 release/remove。线程合并后 settled/归档不等于工作区已删除，也不等于业务验收通过。

详细安装、默认新线程设置和验证边界见 [T3 Code 接入](references/t3-code.md)。

## 写入与恢复

保存 provider、绝对目录、repo、Issue/任务键、分支、基点、所有权句柄及取证来源；句柄不进入 Git/Issue/PR。每次命令明确 cwd，不能在主 checkout、其他 Issue 或相邻仓库写入。未知修改、未跟踪内容、并发占用或身份歧义必须保留现场并停止相关写入。

恢复先重新查询提供者、Git 和任务记录，不把“断线/时间已过”当作释放；不同任务不得共享同一可写目录。用户要求沿用带已有修改的目录时，先取得具体修改归属与保留策略，不能覆盖未知内容。

## 清理

按创建提供者的生命周期清理。独立插件只管理自身工作区；宿主工作区只由宿主清理。确认改动保存/合入、停止服务，并检查 ignored/untracked 文件后再删除。脏、分叉、无法证明已合入时保留，不 force/reset。不将宿主任务归档等同工作区删除。

执行前可用 [provider-policy.mjs](references/provider-policy.mjs) 检查已取证的选择记录；它是本地纯函数校验，不读取凭据或工具状态，不证明声明本身真实，更不替代运行时锁。

项目配置与示例见 [project-settings.md](references/project-settings.md)，只有接入/迁移或配置变更时加载；配置不替代真实工具与所有权证据。
