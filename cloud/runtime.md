# SHW 云端运行规则

本包保留 SHW 原工作流与工程规范，但不携带本地 stdio 启动器、用户配置、二进制下载器或凭据。旧说明中的本机安装、env 文件和 profile 设置是桌面版参考，不是云端配置步骤。产品、Issue、分支、验收和授权边界继续生效。

## 先核对宿主能力

- 无 Git 项目或项目存在 `.shw-workflow-ignore` 时继续遵守原适用范围。
- 从宿主当前实际提供的工具发现连接与参数，不能凭 Skill 中的工具名假定连接成功。按任务所需服务执行最小只读调用；未连接时仅推进不依赖该连接的调查和文档，不能宣称完整交付。
- Gitea 必须使用真实 Gitea MCP。GitHub 连接不能自动代替 Gitea 项目身份、Issue、PR 或 CI。已有网关保持原托管与认证。
- Kubernetes 只用经过认证的远程 MCP，继续保持只读，不回退 kubeconfig、exec 或端口转发。
- DBX 复用已连接的开发数据库 MCP，继续按 `shw-dbx` 核对环境并只读查询。缺连接不能取原始数据库密码代替。
- 用户在宿主支持的安全连接界面配置认证；不把 token 写入插件、仓库、聊天或日志。云端不会继承 Mac/Windows 的 env 文件。网关上的 `GITEA_USERNAME`、`K8S_MCP_TOKEN`、`DBX_MCP_TOKEN` 等部署变量由该服务维护者管理，不在插件中插值。

## 工作区

原 `worktree` MCP 操作本地 Git 文件系统。本云端包不声明远程 worktree，不能把远端 Windows/Mac 返回的绝对路径当作当前沙箱路径。

涉及代码变更时，若宿主提供当前任务可访问的隔离 checkout，且用户已选择或明确授权使用该宿主工作区，按原 Skill 的外部/宿主工作区路径执行：记录项目路径、Issue、分支与基线，所有文件和命令限制在该路径；不调用不存在的 acquire/release/remove，不冒称由 Worktree MCP 管理。只使用宿主公开且已授权的工作区生命周期能力，不手改插件索引或清理宿主管理路径。

没有可访问的代码工作区，或用户要求必须由插件 Worktree MCP 管理时，说明缺失能力，停止依赖工作区的操作；继续完成可执行的只读分析。提供远程 MCP 地址本身不能解决共享文件系统问题。

## 客户端专属能力

原文的 slash commands 是显式 Skill 提示词；云端用 Skill 名或自然语言请求，不假设原生 slash command、fork、任务归档、GUI、Docker 或本机模型 profile 存在。确实需要这些能力时先验证；缺失时报告限制，不伪造验证结果，不绕过发布门禁。

## 验证和完成状态

区分插件已创建、用户已安装、服务已认证、工具只读调用成功，以及真实代码/CI/部署验证。仅有插件包或文档不能证明后几项。原项目外只读、密钥保护与各类审批条件保持有效；云端适配只调整可执行入口，不扩大授权。
