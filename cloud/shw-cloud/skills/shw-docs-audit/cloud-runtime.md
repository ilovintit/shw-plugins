# SHW 账户云技能运行规则

账户云分发不意味着执行环境一定在云端。本包只提供通用技能，不携带本地 stdio、下载器、用户配置或 worktree 技能。基础 MCP 复用用户已经单独云安装并认证的 SHW 连接；不从 Mac/Windows env 文件取凭据，不新建服务，不改认证或权限。

## 工具与权限

执行前发现当前会话实际工具和 schema。已有 SHW 聚合连接的业务工具通常为 `gitea_*`、`dbx_*`、`k8s_*`；宿主可能再加自己的前缀。按服务、工具用途、参数 schema 匹配，不硬编码宿主完整名称，不机械重复拼接前缀。Gitea 与 GitHub 仓库身份不得替换。连接可见不等于每个上游已通；按当前任务做最小只读调用，缺失时明确阻塞并继续独立工作。

已连接工具可能包含写能力，工具暴露不授予业务权限。Gitea 写入仍依任务授权；DBX 继续只查询已核验开发库；Kubernetes 继续只读，明确指定核实的目标/context，不依赖可能指向生产的默认值。禁止用数据库密码、kubeconfig、exec 或新网关绕过连接缺失。不要把网关的“状态已配置”当成上游连通或只读强制保证。

## 工作区与客户端

使用 `shw-workspace`：Codex 本机已安装独立 worktree 时按其真实 claim 操作；云宿主提供已隔离且归属当前任务的 checkout 时保留路径、Issue、分支、基点和证据。同会话已核对的选择不重复确认。缺本地服务不能虚构 claim，也不能在无隔离/占用证明的目录写入；宿主目录只由宿主生命周期管理。绝不把远端绝对路径当成本会话文件系统。

slash 名称仅为技能入口提示；缺原生 slash、归档或 GUI 能力时不要伪造调用。主包与旧本地主 SHW 同时启用会产生重复技能/MCP，应由用户先停用旧本地主包，保留独立 worktree 的状态和配置。

## 工作流

当前正文和集成契约是唯一规则：够用 PRD/方案后直接体验；代码与 PRD/技术文档同步；开发阶段必跑类型与受影响模块快速检查，全量回归留到集成；长周期全量业务回归集中在 dev→main 集成；冻结候选、局部断言/基线重跑、漂移失效、正常 merge 后晋升；tag/审批选择已集成制品。旧云包的 TDD、基线快捷接受或 worktree 必需流程不继续生效。包发布、用户安装、连接认证、只读调用和业务验收分别记录，不能相互代替。
