# 工作区能力契约

先读取 `shw-issue-gate`。纯读调查与已授权元数据操作不创建工作区。文件变更必须先确定 repo、Issue/本地授权任务、来源分支、实际目录和所有者，检查已有任务、分支、PR及工作区，避免重复派工。

## 选择提供者

1. 已有属于当前任务的隔离工作区：核对宿主/提供者返回的真实路径、分支、来源和所有权，再复用。用户明确选择的工作区不自动迁移或删除。
2. 本地安装独立 **shw-worktree** 且工具可用：加载该插件 `shw-worktree` 技能，使用 `worktree` 工具的 acquire/inspect/list/release/remove/reconcile。主 SHW 不注册此工具、不读取或手改其状态和用户配置。
3. 云端或宿主已提供隔离目录：只有宿主证据能确认归属、无其他活动写入者，并且 Git 路由/脏文件检查通过，才使用宿主能力。云端不需要安装本地插件。
4. 本地缺少插件或既有提供者不可用：只读检查现有工作区；不能把工具不可用解释成无占用，不能自动新建同 Issue 分支、复制目录、借他人 claim 或绕过失联提供者。已有明确授权、宿主独占的隔离工作区可继续；否则停止文件写入并报告缺失的所有权/隔离能力。可继续纯读工作，不自动安装插件或改用户配置。

## 写入与恢复

保存 provider、绝对目录、repo、Issue/任务键、分支、基点、所有权句柄及取证来源；句柄不进入 Git/Issue/PR。每次命令明确 cwd，不能在主 checkout、其他 Issue 或相邻仓库写入。未知修改、未跟踪内容、并发占用或身份歧义必须保留现场并停止相关写入。

恢复先重新查询提供者、Git 和任务记录，不把“断线/时间已过”当作释放；不同任务不得共享同一可写目录。用户要求沿用带已有修改的目录时，先取得具体修改归属与保留策略，不能覆盖未知内容。

## 清理

按创建提供者的生命周期清理。独立插件只管理自身工作区；宿主工作区只由宿主清理。确认改动保存/合入、停止服务，并检查 ignored/untracked 文件后再删除。脏、分叉、无法证明已合入时保留，不 force/reset。不将宿主任务归档等同工作区删除。

执行前可用 [provider-policy.mjs](references/provider-policy.mjs) 检查已取证的选择记录；它是本地纯函数校验，不读取凭据或工具状态，不证明声明本身真实，更不替代运行时锁。

项目配置与示例见 [project-settings.md](references/project-settings.md)，只有接入/迁移或配置变更时加载；配置不替代真实工具与所有权证据。
